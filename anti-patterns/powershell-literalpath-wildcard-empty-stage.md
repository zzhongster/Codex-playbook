# 反模式：在 PowerShell 的 LiteralPath 中使用通配符复制目录内容

## 一句话结论

`Copy-Item -LiteralPath (Join-Path $source '*')` 不会展开 `*`；若同时没有失败即停和复制后置校验，部署脚本可能继续运行，并把零文件的空目录误报为成功上传。

## 失败表现

- 目标目录创建成功，但文件数为 0。
- 后续入口脚本报“不存在”，容易被误判为权限、网络或路径编码问题。
- 日志里出现过复制错误，但调用链仍返回了看似成功的最终结果。

## 根因

`-LiteralPath` 按字面解释路径，通配符字符没有特殊含义。若脚本未设置 `$ErrorActionPreference = 'Stop'`，某些非终止错误不会阻止后续命令执行；只检查目录存在也无法证明部署完整。

## 正确做法

- 需要通配符时使用 `-Path (Join-Path $source '*')`。
- 更严格的方案是先用 `Get-ChildItem -LiteralPath $source` 枚举，再逐项复制明确路径。
- 脚本入口设置 `$ErrorActionPreference = 'Stop'`。
- 复制后校验精确文件清单、数量和 SHA-256，而不是只校验目录存在。
- 远端运行使用新的不可变 staging 目录；校验失败时只清理该次精确目录，避免污染或覆盖上一批工具。

## 本次实证

首次 staging 使用 `-LiteralPath` 加 `*` 后，目标工具文件数为 0；改用支持通配符的 `-Path`，并加入文件数与清单校验后，6 个预期脚本完整到位，随后 Windows PowerShell 5.1 解析和远端校准均通过。

## 验证清单

- 复制结果包含全部预期文件，且没有多余文件。
- 每个文件 SHA-256 与发布清单一致。
- 缺失、重复或多余文件都会令脚本非零退出。
- 后续执行从校验完成的 staging 根目录启动。
