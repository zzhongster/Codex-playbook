# 反模式：局部搜索未命中覆盖已取得事实

## 一句话结论

“在某个范围内没找到”是带范围的检索结果，不能覆盖同一章节已经保存的事实。章节状态与每次搜索的状态应分别表达，三种交付都要保留该搜索的范围、地址、时间和限制。

## 场景与失败

2026-10-10，trade-agent-data 的 Buddy O4 分析报告将宿主捕获的公开证据与检索记录投影到聊天、Word 和 Excel。独立集成复核用合成主体通过正常 API 先保存一条风险事件原文捕获，再记录另一个网站的搜索未命中。

原实现的章节仍有一条事件事实，`fact_count=1`，却把章节状态写为 `searched_no_hits`，摘要显示“本次范围内未发现”。交换两条决定的记录顺序也会复现。证据表和章节摘要因此自相矛盾，读者可能把局部未命中理解成否定已经发现的事件。

本例没有真实诉讼或客户信息，没有联网检索或付费调用。证据成熟度是一个项目内的正常 API、合成数据和独立交付读回，不作为跨项目 Pattern。

## 根因

章节投影先按已采用事实计算 `obtained` 或 `partial`，随后用 `any(searched_no_hits)` 无条件覆盖它。检索范围本来只属于一条搜索记录，却被提升为整个章节的判断。单独测试“有事实”和“未命中”两条路径都能通过，混合证据才暴露问题。

## 正确做法

- 已采用事实决定章节的取得或部分状态；用户主张与推断仍保持待核实，不能因搜索结果变成已核实。
- 只有没有已采用事实时，章节才能使用带范围的未发现状态。这个状态仍不证明不存在或没有风险。
- 保存每一条未命中搜索的范围、已打开地址和带时区的获取时间。聊天边界说明与 Word/Excel 公开搜索附录共用同一投影。
- 明确“未命中不否定其他已保存事实”。不能为了修摘要而丢弃未命中记录，也不能把已有事实升级为全面搜索完成。
- 原始捕获和决定记录保留；重算展示与重新渲染不重新查询、不制造新的检索结果。

这里的“事实”指可回溯的原文或数据记录，不表示原文中的所有主张都已经独立证实。来源冲突应另外核对，不能用任一未命中记录自动解决。

## 验证矩阵

| 输入 | 修复后章节状态 | 交付必须保留 |
| --- | --- | --- |
| 原文捕获事实 + 另一范围未命中 | `obtained`，或已有其他限制时 `partial` | 原事实与明确范围的未命中记录 |
| 用户主张 + 未命中 | `partial` | 未独立验证说明及未命中范围 |
| 推断 + 未命中 | `partial` | 推断属性及未命中范围 |
| 只有两次范围未命中 | `searched_no_hits` | 两次各自的范围、URL、时间与不能证明无风险的限制 |

前三项都测试两种决定顺序；不能让到达顺序决定业务结论。还要实际生成并读回三种交付，验证正文摘要、证据表与搜索附录一致，而不是只断言内存状态。
