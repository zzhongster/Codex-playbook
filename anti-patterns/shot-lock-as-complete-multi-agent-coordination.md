# 反模式：把多 Codex 的镜头锁当成全部并发边界

## 一句话结论

多 Codex 共用工作台时，应按镜头、共享素材缓存和正式版本写入分别守住边界；锁不能替代输入冲突检查，项目里的“最新结果”也不能替代镜头归属。

## 场景

2026-10-20，一位用户指挥多个 Codex，共用 ArcReel 资产库和 LibTV 素材交接模块。多个 Codex 可以准备不同镜头，同一角色图会被多条镜头引用。

证据成熟度：`project-validated`。本次验证的是同一台开发机、同一工作目录、多个客户端或进程共享记录；没有验证多主机或共享网络文件系统部署。

## 失败表现

下表区分证据来源，避免把代码审查发现的风险写成已发生的生产事故。

| 问题 | 发现方式 | 后果或实测现象 |
| --- | --- | --- |
| 默认取整个项目最近上传的视频 | 审查发现，补回归 | 多条镜头会错误采用别条镜头的结果；修复后未选择结果时明确停止 |
| 指定镜头与交接记录所属镜头不同 | 审查发现，补回归 | 操作键和真正写入目标可能不一致；修复后下载前即拒绝 |
| 准备记录未包含绑定画布身份 | 审查发现，补回归 | 重绑画布后，旧记录和新上传可能指向不同画布 |
| 镜头锁存在，但共享缓存直接覆盖写入 | 审查发现，补并发回归 | 不同镜头同时下载同一哈希时，可能截断另一方正读的缓存 |
| 锁租约固定600秒却不续约或设围栏 | 审查发现，补回归 | 长上传未结束，另一位 Codex 就可能进入同一执行区 |
| 检查输入与正式写入分开 | 核验原接口不足，扩展后实机验证 | 另一位 Codex 改完镜头，旧结果仍有覆盖窗口；修复后旧快照返回409 |
| 子操作退出时关闭借用的 MCP 连接 | 实机故障 | 准备成功后，下一步回传遇到已关闭连接；修复连接所有权和重连队列后完成闭环 |

## 根因

“只有一个人使用”不等于“只有一个写入者”；多个 Codex 聊天、后台操作和页面操作都是独立参与者。

同样，资源属于不同维度：镜头决定谁可以处理结果，文件哈希决定谁可以发布共享缓存，原生事务决定何时能原子采用结果。一个锁名覆盖不了这些关系。

## 正确做法

### 明确归属，不做猜测

准备与回传记录显式保存项目、剧本、镜头、绑定画布和远端结果身份。回传默认取该镜头已经明确选定的结果；不根据名称相似、上传时间或“最新视频”合并。

交接 ID 与调用参数中的镜头必须一致。项目重绑画布后创建新的准备身份，旧回执仍保留供恢复。

### 锁按资源分层

| 资源 | 本次采用的边界 |
| --- | --- |
| 同一镜头的准备、回传、恢复 | 共享执行入口按目标加锁，冲突调用返回正在处理 |
| 相同内容的上传映射 | 按明确画布、内容哈希、媒体类型复用已完成节点 |
| 跨镜头共享的缓存 | 按缓存哈希加锁；唯一临时文件写完、校验后原子发布 |
| 正式导入与版本选择 | 接收端原生项目/剧本及版本锁内校验输入、当前版本并提交 |

已发布且哈希正确的缓存不再覆盖写；不能只在上传后才发现读到了一份被截断的文件。

本次单机入口使用内核管理的 `flock`，持有期间不因墙钟超时而失效，进程退出后释放。固定 TTL 不是互斥保证；多主机若使用租约，需要另行验证续约、围栏令牌及接收端拒绝过期写入，不能直接照搬单机结论。

### 锁与条件提交同时存在

锁保证经统一入口的多个 Codex 不同时执行同一镜头，但页面和其他合法 API 仍可能修改输入。因此回传还必须在原生正式写入事务内核对冻结指纹与预期当前版本；客户端“先检查后上传”留有竞态窗口。

### 连接所有权明确

业务服务借用外层已经打开的连接时，内层上下文不负责关闭它。自己创建的连接才由自己关闭。重连时创建新的收件队列，并让旧 reader 持有旧队列和旧进程引用，防止旧连接的 EOF 污染新连接。

这与数据幂等是两件事：连接断开后仍应从持久账本及接收端回执恢复，不能因为重连而新建业务操作。

## 验证清单

- [ ] 两个客户端同时进入同一镜头只有一个执行者，不同镜头可独立处理。
- [ ] 活跃执行超过旧 TTL 后，第二个客户端仍不能进入。
- [ ] 两条镜头共享未缓存素材时，另一方不会读取半写文件；稍后继续可复用正确文件。
- [ ] 缺少镜头结果选择、交接 ID 不匹配、画布重绑均经过行为测试。
- [ ] 修改镜头或当前版本后，旧快照在正式写入前被拒绝。
- [ ] 同一操作初次并发导入只有一版；两个实机客户端重放同一结果也不增版。
- [ ] 共享连接完成准备后仍能回传，重连不会消费旧 reader 的断开消息。

本次13项主机测试覆盖锁、身份映射、缓存竞争与恢复等边界；17项固定镜像服务测试包含初次并发只建一版。实机双客户端重放、修改镜头冲突和服务重启另有保存的结果摘要。这些数字是测试数量，不是吞吐量、并发上限或跨主机可用性指标。

## 适用范围

适用于多个代理共享本地工作目录、同一持久账本和原生写入 API 的单机协作。不能推广为分布式锁方案，也不能保证绕开共享入口、直接改运行数据的客户端安全。
