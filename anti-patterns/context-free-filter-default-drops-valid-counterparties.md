# 反模式：统一过滤默认值丢掉合法交易对方

## 一句话结论

“按产品找目标客户”和“查某供应商的全部客户”需要不同的过滤默认值。共享引擎应保留参数是否省略的信息，根据查询场景选默认；显式用户选择优先，工具 schema、描述与执行行为同步。

## 场景

2026-10-12，trade-agent-data 的供应商客户查询出现名单缺行。用户确认平台存在货代过滤逻辑，并要求 MCP 按供应商查客户时默认保留货代，只有明确要求排除时才过滤。

按产品找潜在买家时，排除货代可以降低名单噪声；按已知供应商查交易对方时，货代也可能是记录中的合法交易对方。是否保留其记录，与是否认定其为最终采购决策主体，是两个问题。

本条只总结 MCP 的已复现问题与修复，不声称已经审计或修复平台方代码。企业身份关联另行验证，不能用关闭过滤替代企业隔离。

## 失败表现

固定供应商、日期范围和返回上限，原始总记录数始终为 92。修复前省略过滤参数只返回 13 行，名单记录计 91；显式保留则返回 14 行、名单记录计 92。缺失的一行来自货代过滤，原始记录并没有消失。

名单与总记录数不一致容易被误判为数据源不同或企业关联错误。总数和过滤后的列表本来可以有不同口径，应通过同条件对照定位差异，不能仅凭数字不相等下结论。

## 根因

- wrapper 和共享引擎使用固定 `exclude_forwarders=True`，无法区分用户明确要求过滤与用户省略参数。
- `search_trade` 的工具 schema 同样声明固定 `default=True`，会误导下游 AI 或可能应用默认值的客户端。
- 将一种名单用途的清洗策略推广到所有角色查询，丢失了供应商客户查询需要保留的交易对方。

## 正确做法

在共享判断处保存“未指定”状态，并只修改目标场景的默认值：

```python
def resolve_exclusion(exclude_forwarders, supplier, aggregate_by):
    if exclude_forwarders is not None:
        return exclude_forwarders
    supplier_customer_query = (
        bool(supplier and supplier.strip()) and aggregate_by == "buyer"
    )
    return not supplier_customer_query
```

以上是判断示意；真实改动在交叉维度分派后计算默认，其他聚合分支继续使用原有行为。

- Python 内部用 `None` 表达省略。对外仍是可选 boolean，省略时不发送该键，不要求客户端传 `null`。
- 目标工具 schema 去掉固定 default；工具和参数描述同时明确“按供应商查客户默认保留，只有用户明确要求排除才传 true”。JSON Schema 的 default 是声明，不等于所有客户端都会填值，但它必须与真实口径一致。
- wrapper 原样转发省略状态；已有预设工具明确传入的布尔值继续生效，不全局关闭清洗。
- 保持查询范围、企业身份解析、原始总数、分页与计费不变；筛选策略改变不能扩大到另一个同名企业。
- 本次复用既有 false 分支，不重设计货代识别器。该分支原先还影响占位符清洗，不能声称本次只改变货代分类器。

## 验证清单与实际对照

| 输入 | 修复前返回行数 / 名单记录计数 | 修复后返回行数 / 名单记录计数 |
| --- | --- | --- |
| 省略过滤参数 | 13 / 91 | 14 / 92 |
| 显式 false | 14 / 92 | 14 / 92 |
| 显式 true | 13 / 91 | 13 / 91 |

三组查询的原始总记录数均为 92。行数不等于去重后的企业数；名单记录计数也不在这里解释为独立提单数。正文不保存真实企业身份。

- 固定同一供应商、日期、上限，证明省略结果与 false 的名称及计数一致；真实货代行只在 true 时被排除。
- 覆盖 wrapper、共享引擎和注册 handler 的省略/false/true；使用真实清洗器，不能把清洗器本身 mock 掉。
- 回归空白供应商、产品买家查询、供应商排名和其他预设默认，防止默认变化外溢。
- 核对公开 tools/list：参数可选、单值 boolean、无固定 default，描述与实际行为一致。
- 对共享引擎调用方执行必要回归及黑盒检查；真实质量与正式公网验证分别留证，不能用本地调用替代已部署版本。
- 同时验证同英文名、不同中文注册主体的隔离；关闭货代过滤不应混入另一主体。

## 适用范围

适用于共享查询引擎同时服务“发现目标”与“完整关系追溯”的系统，以及由 schema 和自然语言描述共同驱动的 AI 工具。

这是单项目内已验证的反模式，尚未完成跨项目复现。它不意味着所有角色名单都应默认保留货代，也不意味着返回的货代就是最终采购商。其他系统应先确定业务用途，再选择默认值。
