# 灰盒访问轨道

**证据成熟度：`proposed`**

**适用范围：** 适用于已获准读取部分内部技术资产、元数据或只读运行信息，但没有完整且可验证源码—构建—部署链的产品逆向任务；访问深度始终受任务授权和资产身份限制。

## 适用条件

### 进入/恢复规范

- **进入/恢复门禁：** 每次进入或恢复本轨道，都必须绑定不可变的 `ART-P0-AUTH`，并验证当前 `ART-G0-AUTH` 的 `verdict` 为 `pass`；授权、版本、账号、环境、数据或动作发生变化时，必须重新授权并取得新的 `pass`，旧判定不得沿用。

### 轨道边界

开始前必须有有效 `ART-P0-AUTH`，明确允许读取、复制、查询、执行或反编译哪些资产，规定许可证、第三方权利、数据级别、工具、输出位置和保留期限。灰盒不是“能拿到什么就分析什么”；任何未列明的包、日志、数据库、部署或服务保持不可访问。

本轨道适合以黑盒事实为锚点补强结构解释，或在只能获得部分资产时建立候选技术图谱。若已有完整源码仍无法绑定生产版本或部署身份，也先按灰盒证据上限处理，不能因仓库可读就自动称为白盒运行确认。

## 可用证据

- 获准的软件包、依赖清单、安装清单、构建或容器清单，以及其中可识别的版本与签名元数据。
- 获准的配置、日志、API 文档、只读数据库模式/查询、部署元数据和运行指标；查询限定字段、行数、时间窗和账号，不用只读权限推定跨库或跨租户权限。
- 获准的二进制、资源、符号元数据、调试符号、接口描述和部分源码。反编译输出是 `derived` 证据，必须链接原始制品，不伪装为原源码。
- 合法账号的黑盒观察、发布说明与领域确认可以作为交叉证据；各来源分别保留版本、环境、工具、时间、内容哈希和局限，不能拼成无边界的“系统事实”。

## 逐步流程

1. 先引用[黑盒轨道](black-box.md)中已验证的入口、角色、场景和黑盒事实；没有黑盒运行条件时显式登记运行缺口，不从技术名称倒推用户行为。
2. 建立技术资产清单，为软件包、清单、配置、日志、API 文档、只读数据库、部署元数据、二进制、符号元数据和部分源码记录来源、版本、内容哈希、权限与时间边界。身份不能核对的材料先隔离。
3. 反编译前记录输入制品内容哈希、反编译工具版本、插件/签名库版本、平台、参数和输出哈希。原二进制与反编译派生物分开保存，重复工具或参数生成新派生证据，不编辑输出使其看似源码。
4. 从清单和包定位组件/依赖，从 API 文档与符号建立入口候选，从配置建立值与优先级候选，从日志和只读数据库建立已记录事件/结构候选。所有 `calls`、`reads`、`writes`、`implements` 边都标来源和主张状态。
5. 逐项把候选结构与同版本黑盒事实配对：先比较入口、请求、时间和稳定业务标识，再判断证据是支持、反驳还是只提供替代解释。配置存在与配置被加载、代码可达与路径执行分别建主张。
6. 对关键解释优先请求最小更强证据，例如精确版本日志、部署制品指纹、只读跟踪或获准运行实验；不能安全取得时保留证据上限和未来验证方法。

## 能够证明

灰盒证据可以证明指定制品或快照中存在的文件、符号、接口声明、配置值、模式、依赖和静态结构，也可以确认获准日志或只读查询在记录时间窗内返回了什么。保留输入身份与工具版本时，还能复现“派生输出如何由该制品产生”。

与同版本黑盒或运行证据关联后，灰盒可以提高对入口候选、组件边界、数据流和实现关系的支持强度。证明范围仍限定到被检查资产和场景；每条更强结论都需要类型化链接，不能靠“内部材料”标签自动晋级。

## 不能证明

反编译会丢失或重建名称、类型、泛型/宏信息，并可能混入生成代码；优化、混淆、动态加载和异常处理还会改变可见控制流。由此不能单独证明原始命名、完整类型、源级结构、实际可达路径或开发者意图，也不能把反编译伪代码逐行当作原源码。

配置存在不等于配置在目标环境生效，清单声明不等于组件已部署，日志缺失不等于事件未发生，静态控制流不等于部署行为。部分源码、只读数据库或单个二进制也不能证明整个产品、所有角色或所有版本的内部模型与运行语义。

## 升级路径

### 证据升级规范

- **历史保留：** 新证据必须新建证据项和类型化追踪链接；已有证据、主张、状态历史和 `ART-P4-TRACE` 版本必须保留且保持可寻址，禁止原地改写或删除。

### 实施方式

从黑盒事实到更强证据采用安全的增量路径：先绑定同一版本、环境与稳定标识，再为包/配置/日志/查询/反编译输出新建证据项，形成主张和类型化追踪链接，并更新 `ART-P4-TRACE`。三个访问轨道始终输出同一套**证据项、主张和类型化追踪链接**，轨道变化不改变对象身份。

获得完整源码、构建链或受控运行条件时转入[白盒轨道](white-box.md)或[运行时实验](../core/runtime-experiments.md)，新建 `supports`、`contradicts`、`derived-from`、`implements`、`reads`、`writes` 或 `validates` 链接并保留历史。若更强证据改变结论，发布新主张或取代关系，不删除旧材料、冲突和工具局限。

## 停止条件

### 安全停止规范

- **立即停止：** 一旦发生授权漂移、版本不匹配、不安全写入、敏感信息泄露或环境未绑定，必须立即停止相关执行；在重新授权且新的 `ART-G0-AUTH` 判定为 `pass` 前，不得继续或恢复。

### 轨道特定触发器

出现授权漂移、版本不匹配、不安全写入、敏感信息泄露或环境未绑定时立即停止。发现资产许可证不明、制品哈希变化、数据库权限超出只读、查询可能锁表/耗尽资源、日志夹带未授权租户数据或反编译输出泄露秘密时，隔离材料并按[授权、隐私与安全](../core/authorization-privacy-and-safety.md)披露。

不得用部分访问权限扩展到隐藏服务、账号、租户或数据库，不得主动调用未获准端点、修改配置、附加生产调试器或执行破坏性验证。恢复需要重新确认授权记录、精确资产/生产版本和绑定环境；不能通过换工具或换执行者绕过停止条件。
