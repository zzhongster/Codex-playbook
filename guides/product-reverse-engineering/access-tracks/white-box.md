# 白盒访问轨道

**证据成熟度：`proposed`**

**适用范围：** 适用于已获准读取完整源码及相关构建、测试、部署和运行材料，并能验证源码—制品—目标环境身份的产品逆向任务；源码访问不扩大运行、数据或生产操作权限。

## 适用条件

`ART-P0-AUTH` 必须分别允许源码/历史读取、依赖解析、构建、测试、部署元数据检查和运行观察，并固定仓库提交、工作树状态、构建配置、制品、生产版本、目标环境及数据边界。缺少完整源码并不妨碍分析，但应使用[灰盒轨道](gray-box.md)表达相应上限。

只有源码身份、构建输入、制品身份和目标生产版本能够建立可核对链路时，源码结论才可用于解释该部署。无法合法运行时仍可做静态白盒分析，但运行行为主张遵循[运行时实验](../core/runtime-experiments.md)的非运行分支，不使用 `runtime-confirmed`。

## 可用证据

- 获准的源码仓库、提交与标签、工作树差异、子模块、生成器、构建脚本、锁文件、依赖元数据、编译参数和制品哈希。
- 路由/接口声明、配置默认值与加载代码、数据库模式和迁移、事务/持久化实现、消息/任务/通知消费者及基础设施描述。
- 单元、集成、端到端和迁移测试及其固定输入、覆盖报告、失败记录和工具版本；测试本身是实现意图与已测路径的证据，不自动代表产品覆盖。
- 与源码身份绑定的部署元数据、生产版本/制品指纹、获准日志、只读数据和可复现运行结果。领域文档与黑盒/灰盒证据继续作为独立交叉来源。

## 逐步流程

1. 先建立“仓库提交/工作树 → 构建输入 → 制品哈希 → 部署实例”的身份链，核对源码身份与目标生产版本。任一环不匹配就拆分主张和缺口，不把当前分支解释成线上代码。
2. 从构建入口与运行入口开始，解析应用、命令、服务、批任务和消费者；绘制有版本身份的依赖图，记录静态链接、动态加载、插件、代码生成和外部依赖等不同边界。
3. 从获准产品入口追踪路由、身份与权限检查、输入验证、服务调用和错误映射；沿配置加载路径写出配置优先级、默认值、环境覆盖、远程配置/功能开关及无法静态确定的值。
4. 对状态改变追到事务边界、持久化读写、约束、缓存和审计；继续追踪提交后的事件、队列、调度、文件、Webhook、通知与其他异步副作用，并记录失败、重试、幂等和补偿所有者。
5. 将单元/集成/端到端测试映射到场景与主张，实际运行获准测试并保存通过、失败和覆盖结果。区分人工源码、生成代码、第三方代码、条件编译和死代码候选；生成代码追到生成器及输入，死代码须经入口、引用、构建配置和运行证据共同限定。
6. 选择关键正常、逆向、负向、边界、权限和重试场景做运行确认，把界面、服务、日志、数据与异步结果关联到静态链。运行证据只确认所测版本、配置、角色和路径；未运行分支保持 `statically-supported`、`inferred` 或 `unsupported`。
7. 以产品能力和场景审查依赖图，而非按文件数收尾；对动态调用、运行配置、反射、外部服务和未覆盖路径建立缺口、替代解释和下一验证动作。

## 能够证明

白盒静态证据可以证明指定源码身份中存在的构建入口、运行入口、依赖声明、路由、配置优先级实现、事务与持久化代码、异步副作用路径、测试和显式约束。完整输入与工具版本还可复现某个制品如何生成，并支持精确的结构和可达路径主张。

当源码—制品—环境身份闭合且相同场景取得运行确认时，可以进一步支持已执行路由、配置值、事务结果、持久化变化和异步副作用的限定行为主张。源码、测试、部署与运行证据各保留独立身份，冲突时不以源码“应当如此”覆盖实际结果。

## 不能证明

**代码覆盖率不等于产品覆盖率**：行或分支被执行不代表角色、权限、状态、数据、集成、非功能或业务语义分母已经满足。未覆盖代码也可能由生产配置、动态入口或外部事件触发；死代码候选不能只由一次搜索或覆盖报告裁决。

源码分支、标签、注释、测试用例或测试通过都不能单独证明部署行为；即使测试与源码一致，也可能与生产版本、制品、配置、数据或外部依赖不一致。源代码展示实现候选，不自动证明业务意图、所有运行路径或产品应当如何设计。

## 升级路径

黑盒、灰盒和白盒都输出同一套**证据项、主张和类型化追踪链接**，并持续更新 `ART-P4-TRACE`，不按访问级别复制对象。对白盒新增的源码、测试、制品、部署和运行材料分别新建证据项，用 `derived-from`、`implements`、`calls`、`reads`、`writes`、`supports`、`contradicts` 或 `validates` 连接已有对象并保留历史。

证据升级按“源码身份 → 构建/制品身份 → 部署身份 → 运行场景”逐级绑定；更强证据可以限定、反驳或取代旧主张，但不删除旧观察与证据上限。生产运行暂不可得时记录未来协议和重开条件；获得授权后按[运行时实验](../core/runtime-experiments.md)新建运行记录，而不是把静态状态直接改成运行确认。

## 停止条件

出现授权漂移、版本不匹配、不安全写入、敏感信息泄露或环境未绑定时立即停止相关构建、测试、调试或运行。依赖安装将执行未审查脚本、测试连接真实服务、制品可能发布到生产、数据库迁移或异步消费者可能写入、源码与生产身份断链时，也在动作前停止并隔离影响。

停止后记录仓库/制品/环境最后安全身份、已产生输出、潜在副作用和清理状态，并按[授权、隐私与安全](../core/authorization-privacy-and-safety.md)升级。只有新的或重新确认的授权、匹配版本、只读/隔离边界和恢复方案齐全后才能恢复；源码可读不能作为继续不安全操作的理由。
