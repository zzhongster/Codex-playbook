# 覆盖、质量与冻结

**证据成熟度：`proposed`**

**适用范围：** 适用于对已获授权的产品逆向工程交付定义覆盖分母、分层风险、执行质量门禁并生成可复核冻结快照；不适用于用百分比替代语义审查、用低风险数量掩盖关键缺口，或通过删除未知项、冲突和静态分支限制来美化完成度。

本页细化[目标、范围与完成定义](goals-scope-and-completion.md)的分母覆盖率和[端到端工作流](end-to-end-workflow.md) Phase 7–8。覆盖回答“批准范围内查到了多少”，质量回答“证据是否足以用于目标决策”，冻结回答“评审时究竟使用了哪一版输入”；三者不能互相替代。

## 覆盖模型：先分母后分子

**先定义分母，再计算分子。** 每类覆盖先冻结范围项稳定 ID、包含/排除理由、父子关系、风险级别、目标证据状态和计算规则；调查中发现新项时，通过范围变更加入下一版分母，而不是悄悄改变当前公式。分子只计入达到预先约定证据状态、边界完整且可追到证据的项；名称清单、空记录或未经验证的推断不计入。

| 覆盖维度 | 分母单位与分子门槛 |
| --- | --- |
| 结构覆盖 | 范围内技术资产、组件、入口与依赖边；计入项具有版本身份、定位和经证据支持的类型化关系 |
| 产品覆盖 | 角色 × 产品表面 × 关键场景；计入项有可见入口、前置状态、结果和适用边界 |
| 语义覆盖 | 规则、状态转换、公式、关键语义与不变量；计入项有精确主张、正反例、证据和当前状态 |
| 运行时覆盖 | 已批准的路径 × 版本/角色/配置；计入项有可复现实验与实际结果，非运行项保留缺口而不冒充运行覆盖 |
| 数据覆盖 | 数据对象、字段族、生命周期与数据流；计入项有身份、读写/派生关系、敏感级别和保留语义 |
| 权限覆盖 | 主体/角色 × 资源 × 动作 × 范围/效果；计入项核对允许、拒绝、租户和服务端强制路径 |
| 集成覆盖 | 接口、事件流、文件交换和人工交接；计入项说明身份、触发、成功、失败、重试与责任方 |
| 非功能覆盖 | 已批准的性能、容量、可用性、安全、隐私、可访问性和可运维属性；计入项有可测门槛、环境和结果 |
| 追踪覆盖 | 要求的源对象—关系—目标对象链；计入项的每个节点和边有稳定 ID、状态、版本边界与证据 |

每一维使用互斥且穷尽的四个桶，并强制 `denominator = numerator + unknown_count + conflicting_count + excluded_count`；同一叶子在同一分母版本中只能进入一个桶。静态分支是 G5 的验证分支属性，不是第五个覆盖桶。不同单位不得直接相加形成伪精确总分；跨维总览必须说明权重、聚合公式和舍入方法。聚合数据探针只可能支持其数据或派生事实分子，不能让产品覆盖或运行时覆盖入账。

## 风险分层与未知队列

风险级别由影响、发生可能性、可发现性、可恢复性以及目标决策用途共同决定，并由有权限的人批准。覆盖率始终同时按整体和风险层报告。

| 风险级别 | 典型影响与处置 |
| --- | --- |
| `P0` | 可能导致人身/重大安全、违法违规、跨租户泄露、重大财务错误或不可逆业务中断；立即阻断相关发布和实验，由相应决策权人处置 |
| `P1` | 会显著影响关键业务、迁移连续性、交易判断或大量用户，且补救成本高；在发布前解决或获得明确、有期限的书面风险接受 |
| `P2` | 影响局部、存在可靠绕行或可在计划窗口修复；可带责任人、期限和重开条件进入后续版本，但仍计入缺口 |

为每个维度维护独立**未知队列**，每项包含稳定 ID、父项、风险级别、当前状态、未找到的证据、已搜索分母、影响、下一动作、责任人、期限和重新打开条件。`unsupported`、`conflicting`、断链、未运行路径、不可访问来源和未解释排除均进入队列；“没有发现”不能直接关闭。

发布前所有 **P0/P1** 项必须得到证据化解决，或由拥有相应风险权限的人给出书面接受，列明影响、理由、补偿控制、适用版本、期限和重开条件。P0 是否允许接受由安全、法律和组织政策决定；逆向团队或 AI Agent 无权自行降级或接受。

## G0–G7 质量门禁

门禁建立最小发布链，但编号表达职责分组，不等于 Phase 的数值顺序。后续门禁不能补发前序授权；任一门禁失败时保留已有证据，修复受影响部分后重新执行该门禁及所有依赖门禁。

| 门禁 | 通过条件 | 命名记录 |
| --- | --- | --- |
| `G0` | 目的、系统/账号/环境/数据、允许动作、隔离、保留、停止与披露均由有权限的人批准 | 授权门禁判定 `ART-G0-AUTH` |
| `G1` | 不可变输入身份、八个范围维度、九类覆盖分母、排除、风险层和计算规则已冻结 | 基线门禁判定 `ART-G1-BASELINE` |
| `G2` | 技术资产、入口交叉索引和动态边界可定位；结构事实与业务语义推断分开，未知依赖进入队列 | 技术目录判定 `ART-G2-TECHNICAL` |
| `G3` | 角色、产品表面和场景已与关键纵向切片、类型化边、反证及验证候选共同建立产品追踪 | 产品追踪判定 `ART-G3-PRODUCT-TRACE` |
| `G4` | 能力、旅程、状态、规则、权限、语义和不变量可追到证据；冲突、错误与补偿没有被理想流程吞掉 | 语义模型判定 `ART-G4-SEMANTICS` |
| `G5` | 运行分支和获批非运行分支都按各自必备产物判为 `pass` 或 `fail`；运行确认状态另行记录，不能替代门禁判定 | 验证分支判定 `ART-G5-VALIDATION` |
| `G6` | 九类覆盖率可复算，P0/P1 已解决或获有效书面接受，冲突、未知、链接和质量检查通过 | 审计判定 `ART-G6-AUDIT` |
| `G7` | 人类评审人批准目的专用交付、限制与发布说明，冻结输入和内容身份可重建且处置责任明确 | 发布就绪判定 `ART-G7-RELEASE` |

G0 复用[授权、隐私与安全](authorization-privacy-and-safety.md)的硬门禁；G5 的非运行路径复用 `ART-P5-STATIC` 与 `ART-P5-RUNTIME-GAP`，不得标为 `runtime-confirmed`。G7 `pass` 是生成根摘要和分离式冻结证明前的发布就绪判定；Phase 8 只有在最后生成的证明也有效时才退出。两者都不提高产品主张的置信度或方法成熟度。

## 门禁判定生命周期

每个阶段摘要列出全部 G0–G7 判定，使用以下封闭词汇；判定生命周期是工作流控制，不是[证据与置信度](evidence-and-confidence.md)中的产品主张状态。

| 判定 | 含义 |
| --- | --- |
| `pending` | 门禁适用，但负责 Phase 尚未完成、联合输入尚未齐全，或 Phase 9 已触发重验；它是非终态 |
| `pass` | 负责 Phase 的不可变输入与产物满足当前门禁规则，派生判定记录完整 |
| `fail` | 门禁已经评估且至少一个适用条件不满足；记录失败原因、阻断范围与重开动作 |
| `not-applicable` | 经具名人类批准，门禁在该范围、分支和版本确实不适用；记录依据、期限和重开条件 |

**未来但仍适用的门禁保持 `pending`**，不能记为 `fail` 或 `not-applicable`。`fail` 只能表示已经执行的否定判定；`not-applicable` 不能表示“尚未做到”“环境不方便”或未知。任何 `pass`、`fail`、`not-applicable` 在输入身份变化后回到 `pending`，直到新判定记录生成。

## Phase→Gate 执行映射

下表是唯一执行映射。进入某 Phase 时，尚未轮到但仍适用的门禁保持 `pending`；Phase 结束并不自动通过门禁，必须由对应的 `ART-G*` 派生记录给出判定。

| Phase | Gate | 执行语义 |
| --- | --- | --- |
| Phase 0 | `G0` | 从授权、任务简报和停止/恢复产物判定授权与安全边界 |
| Phase 1 | `G1` | 从不可变基线、范围分母和覆盖/变更规则判定输入与分母冻结 |
| Phase 2 + Phase 4 | `G3` | Phase 2 建立角色、产品表面和场景候选，Phase 4 补齐纵向追踪骨架、反证和切片；二者共同完成产品追踪判定 |
| Phase 3 | `G2` | 从技术资产图谱、入口交叉索引和动态盲区判定技术目录质量 |
| Phase 5 | `G5` | 运行分支按实验、首错、副作用与复现判定；获批非运行分支按静态验证、运行缺口、人工接受、验证上限和未来验证方法判定 |
| Phase 6 | `G4` | 从产品、行为、语义和不变量模型判定业务语义综合质量 |
| Phase 7 | `G6` | 从完整性审计、冲突处置和已接受不确定性判定覆盖与发布风险 |
| Phase 8 | `G7` | 从冻结清单、目的专用映射和发布说明判定可重建发布 |
| Phase 9 | `受影响门禁` | 影响分析先把受影响门禁退回 `pending`，再按其原负责 Phase 与新输入重验；不受影响门禁保留原判定和哈希 |

Phase 2 后 G3 保持 `pending`，直到 Phase 4 的共同输入齐全并完成派生判定。Phase 5 的运行分支和获批非运行分支都必须判为 `pass` 或 `fail`；运行确认是否可得由下节的独立状态表达，不能借 `not-applicable` 消除任何分支义务。

## G5 分支判定

G5 先记录所选分支，再分别计算 gate verdict 与 runtime-confirmation status。门禁判定回答“该分支的强制控制是否齐全”，运行确认状态回答“该范围是否需要、获得或经批准无法获得运行证据”；两个字段不能互相覆盖。

| 分支 | G5 gate verdict | runtime-confirmation status | `pass` / `fail` 判据 |
| --- | --- | --- | --- |
| 运行分支 | `pass/fail` | `required/confirmed` | 开始时为 `required`；只有 `ART-P5-PROTOCOL`、`ART-P5-RESULT`、`ART-P5-EFFECTS` 完整，首错、实际结果、副作用、清理与独立复现通过时才成为 `confirmed` 且 G5 `pass`，否则 G5 `fail` |
| 获批非运行分支 | `pass/fail` | `unavailable-with-approved-static-ceiling` | 只有允许理由、`ART-P5-STATIC`、`ART-P5-RUNTIME-GAP`、`ART-P5-STATIC-ACCEPTANCE`、风险接受、验证上限、适用期限、重开条件和未来验证方法均完整时 G5 `pass`，任一缺失即 `fail` |

**G5 不得使用 `not-applicable`。** 非运行分支只是 runtime-confirmation status 为 `unavailable-with-approved-static-ceiling`，不是验证职责不存在；其 G5 `pass` 只证明静态替代分支治理完整，不产生 `runtime-confirmed`，也不删除后续运行证据缺口。未来验证方法至少写明可用环境/授权出现后要执行的协议、观测点、责任人和触发日期或条件。

G5 与覆盖汇总采用同一确定性会计：获批非运行分支必须满足 `gap_count = runtime.unknown_count + runtime.conflicting_count`，使每个未获运行确认或仍冲突的运行项都留在 gap 产物中；运行分支只有在 runtime 的 `unknown_count` 与 `conflicting_count` 都为零时才可 `pass`。因此，静态分支批准、门禁通过或运行实验的业务结果通过都不能自行清零缺口。

## 门禁判定记录与 Phase 产物

每个 `ART-G*` 都是按固定规则计算的**派生判定记录**：它引用 Phase 产物与人工决定产物的稳定 ID、版本和内容哈希，只保存下方封闭字段。它只包装并引用输入，**绝不替代 Phase 产物**，也不成为产品事实的**第二事实权威**；事实、证据、未知与风险仍以 `ART-P*` 及其引用对象为准。

| Gate | 派生门禁记录 | 明确引用的不可变 Phase 产物 |
| --- | --- | --- |
| `G0` | `ART-G0-AUTH` | `ART-P0-AUTH`、`ART-P0-BRIEF`、`ART-P0-STOP` |
| `G1` | `ART-G1-BASELINE` | `ART-P1-BASELINE`、`ART-P1-DENOM`、`ART-P1-COVERAGE` |
| `G2` | `ART-G2-TECHNICAL` | `ART-P3-ATLAS`、`ART-P3-ENTRY-XREF`、`ART-P3-DYNAMIC` |
| `G3` | `ART-G3-PRODUCT-TRACE` | `ART-P2-SURFACE`、`ART-P2-ROLE`、`ART-P2-SCENARIO`、`ART-P4-TRACE`、`ART-P4-GAP`、`ART-P4-SLICE` |
| `G4` | `ART-G4-SEMANTICS` | `ART-P6-PRODUCT`、`ART-P6-BEHAVIOR`、`ART-P6-SEMANTICS` |
| `G5` | `ART-G5-VALIDATION` | 运行分支引用 `ART-P5-PROTOCOL`、`ART-P5-RESULT`、`ART-P5-EFFECTS`；非运行分支引用 `ART-P5-STATIC`、`ART-P5-RUNTIME-GAP`、`ART-P5-STATIC-ACCEPTANCE` |
| `G6` | `ART-G6-AUDIT` | `ART-P7-AUDIT`、`ART-P7-CONFLICT`、`ART-P7-UNCERTAINTY`、`ART-P7-ACCEPTANCE` |
| `G7` | `ART-G7-RELEASE` | `ART-P8-APPROVAL`、`ART-P8-RELEASE`，以及选定目的的 `ART-P8-REWRITE`、`ART-P8-MIGRATION`、`ART-P8-REPLACEMENT`、`ART-P8-DUE-DILIGENCE` 或 `ART-P8-COMPETITOR` |

### 派生门禁记录字段

| 字段 | 确定性内容 |
| --- | --- |
| `gate record ID` | 由 gate、schema、规则和输入内容身份确定的稳定记录 ID |
| `gate ID` | G0–G7 中被计算的唯一门禁 ID |
| `schema version` | 本字段集合与序列化规范的固定版本 |
| `rule version` | 用于计算判定的规则内容身份 |
| `input artifact IDs/hashes` | 被验证 Phase 产物的稳定 ID、版本和内容哈希 |
| `human-decision artifact IDs/hashes` | 已存在的不可变人工决定产物稳定 ID、版本和内容哈希 |
| `verdict` | 按规则计算的 `pending`、`pass`、`fail` 或允许范围内的 `not-applicable` |
| `derived reason codes` | 由规则和输入确定的规范原因码集合，按稳定顺序输出 |
| `generator version` | 执行规则的生成器内容身份与固定参数版本 |

### 分离执行元数据

作业 ID、执行主机和执行时间属于分离的运行日志，不进入确定性身份，也不进入 ART-G 字段、内容哈希或判定；重新运行同一规则与输入时即使执行时间不同，也必须产生相同 ART-G。人工决定产物 ID/哈希保留在确定性字段中，但决定人的身份、决定时间、决定内容和证明只存在于被引用的不可变人工决定产物，不能复制或推导到 ART-G。

派生记录必须可由同一输入哈希和规则版本确定性重建。重建得到不同判定时 G6/G7 不能通过；修正规则或 Phase 产物会创建新版本及生命周期关系，不回写旧判定记录。

## 人类决定与派生门禁的边界

人工授权、非运行分支接受、高风险接受和发布批准分别写入 `ART-P0-AUTH`、`ART-P5-STATIC-ACCEPTANCE`、`ART-P7-ACCEPTANCE`、`ART-P8-APPROVAL`。它们是先由有权限的人签署、再按稳定 ID、内容哈希和版本冻结的**不可变输入**；变更决定必须发布新版本，旧版本按产物生命周期保留。

人工决定先于门禁判定。`ART-G0-AUTH`、`ART-G5-VALIDATION`、`ART-G6-AUDIT`、`ART-G7-RELEASE` 只按固定**规则版本**验证对应人工决定的签署权限、适用范围、期限与输入哈希，并引用验证结果。门禁生成器不得生成评审者身份、批准时间、决定或签名，也不得从聊天、作者名或默认配置补齐它们；缺少决定输入时只能给出 `pending` 或 `fail`。

生成的 gate metadata 只能包含**派生且固定的来源元数据**，例如规则版本、输入 ID/哈希、确定性计算结果和生成器版本。评审者身份、批准时间、接受理由、决定与签名属于人类决定产物；门禁记录引用其哈希而不复制成第二份权威。带人工接受的任何门禁都遵守同一依赖方向。

## 父子汇总与确定性生成

分母以可追踪的**父项**和**子项**组成。叶子子项是默认计算单位；父项状态由预先声明的聚合规则派生，不能既把父项又把全部子项重复计入同一分子。父项通过至少报告 `covered / total / unknown / conflicting / excluded`，并保留每个子项稳定 ID；父项关键性不能被大量低风险子项平均掉。

生成器执行**确定性生成**：冻结输入按稳定 ID 和声明顺序排序，固定工具版本、参数、模式版本、区域设置、时区、编码和舍入规则；时间戳等非确定字段写入单独清单，不参与语义内容身份。相同输入运行两次应产生逐字节相同的受控输出，否则记录差异并阻止冻结。

每次生成声明**输出允许列表**，只允许列出的报告、索引、清单和派生文件进入冻结候选；意外文件、缓存、临时导出和敏感内容使 G6 失败。清单为每个输入、允许输出、生成器和模式记录**内容哈希**、大小、媒体类型、逻辑 ID 与来源关系；目录修改时间和文件名不能替代内容身份。

| 汇总检查 | 要求 |
| --- | --- |
| 唯一计数 | 每个叶子只属于声明的聚合路径；共享项用引用，不复制计数 |
| 风险保持 | 父摘要分别显示 P0/P1/P2，不以整体平均隐藏关键项 |
| 可解释状态 | 未知、冲突、排除、静态验证和运行确认保持独立桶 |
| 双向导航 | 父摘要可下钻到子项，子项可返回分母版本、证据和父摘要 |

## 阶段摘要记录

每个阶段退出时生成一个可寻址、可验证的阶段摘要记录。阶段摘要是独立包络；阶段状态属于工作流记录，不是产品主张状态，摘要不能用“完成”一词吞掉未知、风险或失败门禁。字段按以下契约固定：

| 字段 | 必填内容 |
| --- | --- |
| `phase ID` | 限定命名空间中的稳定阶段实例 ID，不因标题或输出路径变化而复用 |
| `status` | 候选、执行中、受阻、已评审或已冻结等明确工作流状态及状态原因 |
| `target/version and scope identity` | 目标产品、构建/版本、环境或克隆，以及本阶段范围版本和内容哈希 |
| `frozen denominator` | 本阶段使用的分母版本、稳定 ID 清单哈希、排除规则和计算规则身份 |
| `input hashes` | 所有直接输入、证据索引、配置、模式和生成器的内容哈希及逻辑 ID |
| `child-summary hashes` | 每个直接子阶段/子任务的摘要 ID、不可变内容哈希和使用版本 |
| `output allow-list and hashes` | 允许输出的相对路径或记录类型，以及实际输出的逻辑 ID、内容哈希和偏差 |
| `coverage/unknown/risk counts` | 按覆盖维度和 P0/P1/P2 分列的分母、覆盖、未知、冲突、排除与风险接受数量 |
| `G0–G7 gate verdicts` | 每个门禁的 `pending`、`pass`、`fail` 或 `not-applicable` 判定，依据记录、决定人、期限和重开条件 |
| `owner` | 对摘要完整性、门禁升级和后续更正负责的具名人类责任人 |
| `timestamp` | 由冻结流程一次写入的时区明确时间；重建时复用该值，不读取当前时钟 |

**父阶段只消费不可变子摘要**的稳定 ID 与内容哈希，按父阶段预先冻结的聚合规则汇总计数和门禁；它可以沿链接审计子证据，但**不得重新解释子项事实**、改写子主张状态或丢弃子未知。子事实需要更正时，由子项所有者发布新摘要并使用下节的产物生命周期关系；父阶段据此生成新版本，不回写已冻结父摘要。

阶段摘要作为包络，**不得列入自身的 `output allow-list and hashes`**，也不得把自哈希写回任何会参与自哈希计算的字段。摘要哈希只出现在父摘要或冻结清单；没有父阶段的根摘要由冻结清单持有其哈希。这样既能验证完整包络，又不会形成递归自哈希。

时间戳是冻结输入的一部分：首次签署后保持固定，确定性重建不得注入当前时间。摘要哈希覆盖上述包络字段；任何输入、子摘要、门禁或输出变化都会产生新的摘要身份，并使依赖它的父阶段重新验门。

## 产物与摘要生命周期

产物与阶段摘要使用独立于产品主张状态的生命周期；它不能复用 `observed`、`runtime-confirmed` 等主张状态，也不能用主张状态表达文件是否仍为当前版本。

| 生命周期 | 含义 |
| --- | --- |
| `active` | 当前范围中可被新门禁判定、父摘要或冻结清单引用的产物/摘要版本 |
| `replaced` | 已由一个明确的新产物/摘要版本取代；旧对象保持可寻址且不得再作为当前输入 |
| `withdrawn` | 因无效、越权、敏感泄露或不再发布而撤回，当前没有可自动替代的有效版本；保留原因和影响 |

新产物/摘要用 `replaces` 指向旧对象，旧对象用 `replaced-by` 回指新对象，并记录理由、批准人、生效范围和时间。关系必须成对且目标哈希存在；撤回使用 `withdrawn` 和撤回记录，不伪造替代对象。产品主张的 `superseded` 仍只按[证据与置信度](evidence-and-confidence.md)用于主张取代，两套生命周期不得互换。

## 无环冻结生成顺序

冻结必须按下列顺序单向生成，任何一步变化都从该步开始产生新版本，不能向前写回哈希：

1. `content outputs`：生成证据/主张索引、普通 Phase 产物、目的专用映射、发布说明、不可变人工决定和派生门禁记录；固定每个允许输出的内容哈希。本步明确排除所有阶段摘要、根摘要和分离式冻结证明。
2. `child/phase summaries`：从叶子到父级生成阶段摘要；每份摘要都排除自身包络和所有证明，只引用已经存在的内容输出和子摘要哈希。
3. `root summary`：生成根摘要 `ART-P8-ROOT-SUMMARY`，汇总不可变子摘要、门禁和声明输出；根摘要同样不包含自身哈希或任何冻结证明。
4. `detached freeze manifest/attestation`：最后生成分离式 `ART-P8-FREEZE`，它哈希根摘要和全部声明输出，并记录生成规则、签署或提交锚点。

分离式冻结清单/证明位于每个阶段摘要的输出哈希集合之外；任何摘要也不把 `ART-P8-FREEZE` 当作输入或子项。`ART-P8-FREEZE` 的自身完整性由 Git commit 或外部签名锚定，不把其 Git 对象或签名写回自身，也不得递归包含自身哈希。验证顺序相反：先验证外部锚，再读取分离式清单，然后验证根摘要、子摘要和内容输出。

## 冻结输入、更正与指标防篡改

**冻结输入**至少包括授权版本、范围/分母清单、环境与源码/制品身份、证据目录、主张及状态历史、覆盖算法、风险接受、生成器/模式版本和输出允许列表。冻结清单使用内容哈希和稳定 ID 指向不可变快照；只冻结路径名或当前分支不满足可重建要求。

冻结后不原地改写历史事实。发现错误时新建更正记录和新快照，将旧主张标记为 `superseded`，使用 `replaces` 类型化链接说明**取代**关系、原因、影响、评审人和生效边界；旧记录仍可寻址。若证据冲突未消解，保持 `conflicting`，不能用新版本文件覆盖旧证据。

不得删除未知项来改善指标，也不得把排除、失败、冲突、不可复现或静态分支项改名后移出分母。合法范围变更生成新分母版本，保留旧版本、变更理由、批准人和变更前后重算结果。未知被新证据解决时保留状态历史；风险接受到期、版本变化或重开条件触发时，相关项自动回到活动队列并使受影响门禁失效。

## 冻结产物与复核

发布包包含分母与覆盖报告、未知/冲突/排除清单、P0/P1 接受记录、证据和主张索引、生成清单、允许输出哈希、目的专用交付、可用于/不可用于的决定以及下一次复核条件。评审者应从空目录使用冻结命令重建输出，核对哈希、链接、计数和随机抽样证据；机器一致不代表产品语义正确，仍需相应人类决策权人签署。

非运行分支限制在父摘要、G5、G6、G7 和发布说明中持续可见。运行证据后来补齐时新建证据与主张状态变更，并通过各自适用的主张取代关系、产物生命周期或新冻结版本发布，不能回填旧快照使历史覆盖率看似更高。
