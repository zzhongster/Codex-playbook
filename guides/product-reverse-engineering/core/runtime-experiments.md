# 运行时实验

**证据成熟度：`proposed`**

**适用范围：** 适用于在已通过授权门禁、可隔离且可恢复的环境中验证产品运行行为；不适用于生产环境破坏性探测、未授权账号或数据，也不允许把基础设施可达、聚合数据结果或静态证据解释为已观察到的界面与产品行为。不能合法、安全运行时使用本页的非运行分支。

运行时实验把[端到端工作流](end-to-end-workflow.md) Phase 5 的运行分支展开为可复现实验协议。实验只回答限定版本、角色、配置、数据与时间窗内发生了什么；方法是否成熟与产品主张真假仍按[证据与置信度](evidence-and-confidence.md)的四个独立轴记录。

## 环境身份、基线与探针安全

每次运行先分配实验 ID，并冻结**不可变环境身份**：产品版本与构建号、部署实例或克隆 ID、操作系统与运行时、依赖版本、配置内容哈希、功能开关、时区与时钟来源。显示名称和“测试环境”标签不能充当身份；环境、构建或关键配置一旦变化，就新建实验运行记录，不覆盖旧身份。

执行前建立**基线**，记录测试对象状态、关键表或接口的只读快照、队列积压、外部连接状态、账号权限和资源指标。源码与部署件分别记录**源码指纹**和二进制/制品指纹；从数据库或虚拟机复制的环境另记**克隆指纹**、源快照身份、复制时间与脱敏方法，使“分析了什么”和“运行了什么”能够相互核对。

数据使用不会碰撞真实业务键的**唯一哨兵**，例如由实验 ID、运行序号和随机后缀组成的合成标识。哨兵不得含个人信息或秘密，并要贯穿界面、网络、日志、数据库、消息和清理清单，以区分本次副作用与基线既有数据。

先规划**只读探针**，再规划可能改变状态的**写入实验**；读取、写入、故障注入和清理权限分开批准，不能用读取授权推定写入授权。写入实验只使用专用测试账号、独立租户或组织以及可恢复的安全克隆；专用测试账号采用最小权限并保留独立审计身份，安全克隆需验证隔离、外发抑制、恢复点与处置责任。无法证明与真实用户、生产数据和真实外部系统隔离时停止运行。

| 运行前记录 | 最低内容 |
| --- | --- |
| 环境身份 | 实验 ID、产品/构建、部署或克隆 ID、依赖、配置哈希、时间基准 |
| 来源身份 | 源码指纹、制品指纹、克隆指纹、源快照和脱敏记录 |
| 安全边界 | 测试账号、租户、网络出口、允许操作、成本/速率上限、停止条件 |
| 数据基线 | 前置对象、唯一哨兵、关键计数/状态、队列和外部依赖状态 |
| 恢复能力 | 恢复点、逆向动作、责任人、验证方法和最长恢复时间 |

## 三类探针与主张边界

三个层次必须生成不同的观察记录和主张，不能借“更底层、更准确”跨越语义边界。

| 探针层次 | 能直接支持的观察 | 不能据此声称 |
| --- | --- | --- |
| 基础设施可达性 | 指定时间内端口、进程、主机或服务端点可连接及其低层响应 | 业务功能可用、权限正确、界面成功或数据语义成立 |
| 聚合数据探针 | 限定查询、快照或指标返回的计数、分布与时间范围 | 单条业务对象的生命周期、用户所见结果或产生聚合值的产品规则 |
| 观察到的产品行为 | 指定角色按协议执行动作时的可见反馈及已核对副作用 | 未测试角色、配置、路径、时间或其他版本中的普遍行为 |

基础设施可达不等于产品行为成立；它只能支持可达性主张。**聚合数据探针不能升级界面或产品行为主张**：聚合结果即使与预期一致，也只支持该查询和样本边界内的派生事实，除非另有同场景用户操作与副作用证据。三类证据可以通过类型化链接共同支持一个限定解释，但不得合并成没有来源边界的单条“系统正常”结论。

## 实验协议与观察记录

实验协议 `ART-P5-PROTOCOL` 在执行前固定：目标主张与替代解释、不可变环境身份、角色与测试账号、前置基线、唯一哨兵、输入、单步操作、变量、观测点、**预期结果**、停止条件、逆序清理和复现判据。每次运行另记开始/结束时间、执行者、工具版本、**实际结果**、偏差和证据 ID；预期与实际分栏，禁止事后改写预期来匹配结果。

| 观察面 | 必须保存的内容 |
| --- | --- |
| 界面 | 入口、角色、动作顺序、可见状态、消息、时序以及脱敏截图或录制引用 |
| 网络 | 请求身份、端点、方法、关键头/体摘要、响应、重试、时序与脱敏抓包引用 |
| 日志 | 来源服务、级别、关联/追踪 ID、首个异常、时间基准和脱敏原文引用 |
| 数据库 | 执行前后行/字段变化、事务结果、审计记录、查询身份、快照或查询哈希 |

消息、缓存、文件、通知、外部调用和性能指标按场景增列，不能因四个基本观察面已填就假定没有其他副作用。用户看到成功而数据库或异步副作用未完成，以及后台已完成而用户没有收到反馈，均分别记为实际结果。

**可重复步骤**必须从已知基线开始，逐步写明输入、动作、等待条件和每个观测点，不依赖执行者记忆。一次只改变一个被研究变量；不能控制的变量列为限制，并降低相应主张的置信度。

## 路径矩阵与首错保全

正常路径只是对照，不是完成条件。按风险和分母选择以下路径，并为每条路径分别定义预期、禁止副作用与终止状态：

| 路径 | 最低实验问题 |
| --- | --- |
| 负向 | 无效输入、前置条件不足、权限拒绝时在哪一层失败，哪些副作用必须不发生？ |
| 边界 | 空值、最小/最大值、精度、时间边界、容量阈值与批次边界如何处理？ |
| 并发 | 同对象竞争、重复提交、锁与版本冲突如何呈现，谁最终成功？ |
| 重试 | 谁触发、使用什么幂等身份、次数与退避如何限制，是否出现重复副作用？ |
| 故障注入 | 在获准的依赖失败、超时或部分提交点，错误、回滚、补偿和告警是否可见？ |
| 逆向 | 撤销、冲销、退款、退回或恢复是否关联原动作并恢复声明的不变量？ |

任何自动重试前先保存**首个失败**的界面、网络、日志、数据库状态和时间关联。首个失败不得被重试覆盖；后续尝试使用新的运行序号并链接首错证据。部分成功分别记录已提交与未提交步骤，禁止用最终成功擦除中间失败、补偿或重复写入。

故障注入是独立的写入/干扰授权类别。注入范围、爆炸半径、最长持续时间、成本上限、停止开关和恢复负责人有一项不明确，就只登记该路径为运行证据缺口，不执行实验。

## 逆序清理、完整性与处置

清理不是删除哨兵记录后宣告完成。按副作用发生顺序的相反方向执行**逆序清理**：先阻止新异步工作和外发，再撤销下游通知/文件/消息，处理队列与缓存，恢复数据库与业务对象，最后撤销临时账号、权限、配置和网络规则。业务需要使用正式逆向动作时，不用直接数据库删除代替产品语义。

清理后做**完整性核对**：重跑基线查询，验证业务不变量、引用、审计链、队列、缓存、文件、通知和外部模拟器；将预期基线、实际状态和差异逐项记录。随后做**残留检查**，按唯一哨兵搜索获准的界面、数据库、日志、对象存储、消息和导出位置，明确已删除、依法保留、无法触达或超出授权的副本。

实验材料依数据分类执行保留、脱敏和销毁。`ART-P5-EFFECTS` 至少记录每个写入或外发、逆向动作、恢复验证、残留、责任人和**处置证明**；不能安全清理或无法解释完整性差异时立即停止后续运行并走安全披露路径，主张不得因测试步骤完成而晋级。

## 可复现性与结论状态

关键实验的可复现门槛是：**另一执行者**在同一冻结协议和等价不可变环境身份下，能从记录的基线执行可重复步骤，得到位于预先容差内的实际结果，并核对相同类别的副作用和清理结果。重复次数、样本选择、随机种子、等待条件、工具版本、内容哈希与差异全部进入 `ART-P5-RESULT`。

只对实际运行覆盖的版本、角色、配置、数据和路径使用 `runtime-confirmed`。结果不稳定时保留每次运行，主张可设为 `conflicting` 或降低置信度；探针失败只说明该尝试 `failed`，不证明能力不存在。当环境身份不完整、无法复现、关键观测缺失或证据不足以支持目标主张时，主张使用 `unsupported` 或更弱且准确的限定主张，不把“未找到”写成“不存在”。

## 非运行分支

仅当**授权未覆盖运行**、**合法环境不可用**、**依赖或硬件无法安全复现**，或**副作用无法隔离**时，按 Phase 5 选择非运行分支；节省时间、费用或避开失败路径不是理由。建立 `ART-P5-STATIC`，记录源码、模式、配置、文档和领域证据、工具版本、步骤、反证与替代解释；同时建立 `ART-P5-RUNTIME-GAP`，逐条记录缺失运行证据的主张、影响和最高允许状态，并由有权限的人签署不可变的 `ART-P5-STATIC-ACCEPTANCE`，记录分支批准、风险接受、验证上限、期限、重新打开条件与未来验证方法。

必须依赖运行才能成立但没有运行证据的主张保持 `unsupported`；静态证据充分时，可以另建限定的 `statically-supported`、`inferred` 或 `conflicting` 主张，但不得标为 `runtime-confirmed`。非运行分支可以按[端到端工作流](end-to-end-workflow.md)进入后续阶段，但只有三个 Phase 产物齐全时 G5 才能按本分支判为 `pass`，否则为 `fail`；运行确认状态单独保持 `unavailable-with-approved-static-ceiling`。其限制必须持续出现在覆盖、冻结和发布说明中，不能由聚合探针、文档完整度或人工方便性消除。
