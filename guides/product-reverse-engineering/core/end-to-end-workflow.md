# 端到端产品逆向工程工作流

**证据成熟度：`proposed`**

**适用范围：** 适用于对已获授权的软件产品、遗留系统或跨技术栈业务流程开展可追溯的静态分析、运行验证和决策交付；不适用于绕过访问控制、获取未授权数据、在生产环境进行破坏性探测，或用流程完成度替代产品事实的证据强度。

本工作流把逆向工程拆成十个带进入条件和退出门禁的阶段。阶段编号表达依赖关系，不要求人员串行工作；只有上游门禁已经满足、风险例外已由有权限的人接受，后续产物才能进入正式证据链。产品主张的真假与可信程度始终使用[证据与置信度](evidence-and-confidence.md)中的主张状态、置信度和证据引用表达；页首成熟度只描述本页方法的支撑证据成熟度。

## 最小追踪闭环

每条进入评审或验收的关键能力至少完成一次以下闭环：

`角色/入口 → 交互 → 代码/服务 → 数据/异步副作用 → 规则 → 实验 → 决策 → 验收`

闭环中的每个节点使用限定稳定 ID，每条边标明关系类型和证据。无法到达的节点保留为缺口，并把相关主张标为 `inferred`、`unsupported` 或 `conflicting`；不得用文件名、界面标签或一次成功运行填充整条链。只允许静态分析时，“实验”节点记录不可运行的原因和替代验证，不能把结果标为 `runtime-confirmed`。

## 十阶段执行卡

### Phase 0

**阶段目标：授权、目标与安全。** 在任何采集或执行前，固定决策用途、权限边界、数据处理规则和停止机制。

#### 进入条件

- 有可识别的任务发起人、预期决策和候选系统范围。
- 尚未对目标系统执行采集、导出、运行、抓包或写入动作。

#### 执行动作

1. 按[目标、范围与完成定义](goals-scope-and-completion.md)选择一个主要目的，记录决策人、使用者、不用于哪些决策以及完成门槛。
2. 按[授权、隐私与安全](authorization-privacy-and-safety.md)逐项执行 G0，分别确认系统、版本、账号、租户、环境、数据类别和允许动作。
3. 明确最小权限、脱敏、保留与删除、外部副作用、隔离、恢复、异常披露和人工复核责任。
4. 为授权撤销、越界迹象、真实用户影响、敏感数据暴露和不可恢复副作用设置可执行的停止触发器。

#### 交付物

- **任务授权包 `ART-P0-AUTH`**：授权人、有效期、允许来源、允许动作、数据边界和禁止事项。
- **决策任务简报 `ART-P0-BRIEF`**：主要目的、八个范围维度的初始边界、负责人和完成定义。
- **停止与恢复卡 `ART-P0-STOP`**：触发器、紧急联系人、隔离动作、恢复步骤和证据保全要求。

#### 退出门禁

- G0 所有适用项均有明确答案、责任人和有效期；没有用“技术上可访问”代替授权。
- 主要目的、安全边界和不可接受风险已获有权限的负责人批准。
- 团队能在不查看敏感值的情况下说明何时必须停止、由谁决定恢复。

#### 常见失败模式

- 先抓取或运行再补授权，导致证据本身无法合法使用。
- 把重写、迁移和竞品研究混成一个目的，使相同观察被用于不兼容的决策。
- 只准备回滚脚本，却没有定义何时触发、谁有权中止。

#### 停止规则

授权范围、数据权利、测试副作用或恢复责任任一项不明确时立即停止相关活动；只可继续不触及该边界的离线规划，并由授权人书面决定是否恢复。

### Phase 1

**阶段目标：基线与分母。** 固定版本、配置和范围分母，使覆盖率与后续差异有可计算基准。

#### 进入条件

- `ART-P0-AUTH` 与 `ART-P0-BRIEF` 已通过 Phase 0 门禁。
- 能识别至少一个获准分析的版本或构建；无法识别时已有明确的升级路径。

#### 执行动作

1. 记录产品版本、构建标识、部署批次、配置、依赖、时间窗和数据快照身份，区分已观察值与待验证候选。
2. 对版本、角色、产品表面、技术资产、业务能力、数据、集成和非功能八个维度分别列出包含、排除及允许的不确定项。
3. 先枚举稳定分母项，再开始深入阅读；为每项分配稳定 ID、风险级别、期望证据状态、负责人和排除理由。
4. 约定整体与关键项覆盖门槛、可计入分子的主张状态，以及范围变更的批准和留痕方式。

#### 交付物

- **基线清单 `ART-P1-BASELINE`**：版本、环境、配置、依赖和快照的可复核身份。
- **范围分母台账 `ART-P1-DENOM`**：八个维度的稳定对象与场景集合。
- **覆盖与变更规则 `ART-P1-COVERAGE`**：门槛、计数公式、风险分层和范围变更日志格式。

#### 退出门禁

- 每个纳入项都有稳定 ID，每个排除项都有理由；关键项不会被低风险数量稀释。
- 基线能够区分版本、配置和数据快照，且覆盖率算法可由另一名评审者复算。
- 分母所有者已批准初始快照，新增或删除范围项必须走变更记录。

#### 常见失败模式

- 先挑容易理解的文件，再用已经读过的内容反推分母。
- 把仓库文件数当作业务能力分母，或用删除难项提高覆盖率。
- 混合多个版本的证据，却不给主张标注适用版本。

#### 停止规则

无法确定目标版本、关键配置或分母批准人时停止计算覆盖率和发布范围结论；先回到 Phase 0 收紧任务边界，不能用模糊基线继续累计“完成”项。

### Phase 2

**阶段目标：产品表面与角色。** 从参与者可接触的产品地图出发，建立角色、入口和场景候选，而不是从文件目录推断产品。

#### 进入条件

- `ART-P1-BASELINE` 和 `ART-P1-DENOM` 已冻结为本轮基线。
- 已明确哪些界面、API、批任务、报表、通知和外部入口允许观察。

#### 执行动作

1. 按角色盘点页面、命令、API、报表、批处理、导入导出、通知和运维入口，记录可见条件与版本。
2. 区分人员角色、服务身份、权限档位、代理关系和职责分离；不把账号名称直接当作角色定义。
3. 用“角色—目标—入口—预期结果”建立产品地图，再关联候选业务能力和用户旅程。
4. 为正常、负向、逆向、重试、部分成功、批量和权限路径建立场景候选及优先级。

#### 交付物

- **产品表面目录 `ART-P2-SURFACE`**：带稳定 ID、角色、可见条件和证据来源的入口清单。
- **角色与职责图 `ART-P2-ROLE`**：人员、服务身份、权限档位及职责边界。
- **场景候选池 `ART-P2-SCENARIO`**：各类路径、风险、前置状态和期望证据级别。

#### 退出门禁

- 每个关键角色至少关联一个获授权的入口，每个关键入口都有角色与可见条件。
- 产品地图在任何逐文件业务叙述之前完成，并与分母台账双向引用。
- 未观察到的入口明确标为候选或缺口，没有被描述成不存在。

#### 常见失败模式

- 把菜单名称或路由列表当作完整业务能力清单。
- 只记录管理员正常路径，遗漏低权限、服务身份和异常路径。
- 用源码目录结构主导产品分类，导致跨模块旅程被拆散。

#### 停止规则

发现未授权角色、租户或产品表面时停止对该对象的探测；角色身份与真实用户无法隔离时，不得登录或执行路径，只保留已批准的静态候选记录。

### Phase 3

**阶段目标：技术图谱。** 描绘实现拓扑、数据流和运行边界，为选择纵向切片提供定位，不提前宣告业务语义。

#### 进入条件

- `ART-P2-SURFACE`、`ART-P2-ROLE` 和 `ART-P2-SCENARIO` 已可用于选择入口。
- 获准读取的源码、二进制、配置、模式和部署件已有资产清单。

#### 执行动作

1. 识别客户端、服务、库、进程、部署单元、数据库、队列、调度器、文件交换和外部系统的稳定身份。
2. 从产品入口向下定位事件处理器、接口、服务入口、持久化、异步消费者及外发通道，记录别名而不强行合并同名对象。
3. 绘制调用、读取、写入、发布、订阅和部署关系；为每条边记录来源、版本和当前主张状态。
4. 标出权限边界、事务边界、进程边界、租户边界和无法解析的动态调用，形成优先验证队列。

#### 交付物

- **技术资产图谱 `ART-P3-ATLAS`**：组件、部署、数据和集成对象及类型化关系。
- **入口交叉索引 `ART-P3-ENTRY-XREF`**：产品表面到代码、服务和数据候选位置的映射。
- **动态边界清单 `ART-P3-DYNAMIC`**：反射、插件、配置路由、异步和外部依赖等静态盲区。

#### 退出门禁

- 关键产品入口可以定位到至少一个实现候选，无法定位项进入缺口队列。
- 图谱明确区分技术结构事实与业务语义推断，所有跨边界链接都有类型。
- 团队能据此选择代表性、高风险和冲突性纵向切片。

#### 常见失败模式

- 把搜索命中或同名字段直接解释为调用关系和业务含义。
- 只画同步主路径，遗漏事务、消息、定时任务和外部副作用。
- 生成巨大依赖图却没有入口、版本、边类型和取证优先级。

#### 停止规则

定位过程触及未授权仓库、凭据、外部服务或数据域时停止沿该边扩展；动态调用无法静态解析时登记缺口，不以猜测补成确定关系。

### Phase 4

**阶段目标：纵向证据链。** 以少量高价值场景贯通角色、交互、实现、数据、规则和验收，验证图谱是否真的支持产品解释。

#### 进入条件

- `ART-P3-ATLAS` 与 `ART-P3-ENTRY-XREF` 足以选择一个代表性或高风险切片。
- 场景的角色、前置状态、入口、版本和允许观察范围已固定。

#### 执行动作

1. 为切片建立角色、入口、交互、代码/服务、数据/异步副作用和规则节点；实验、决策和验收先建立计划/候选占位节点，分别由 Phase 5 的验证和 Phase 8 的目的决定与验收补入实际结果。
2. 沿同步与异步路径追踪读取、验证、转换、写入、提交、通知和补偿，给节点和类型化边分配稳定 ID。
3. 把直接观察、静态支持、运行确认、领域确认和推断分开登记，同时搜索反驳证据与替代解释；占位是追踪图的执行阶段标记，不是新的产品主张状态。
4. 将断点、版本差异、未知调用和不可运行条件登记为缺口；选择下一个切片时兼顾代表性、风险和冲突。

#### 交付物

- **纵向追踪包 `ART-P4-TRACE`**：追踪图骨架、已取证节点、计划/候选占位节点、类型化边和适用边界。
- **断点与反证簿 `ART-P4-GAP`**：链路断点、反驳证据、替代解释和验证计划。
- **切片选择记录 `ART-P4-SLICE`**：纳入理由、分母覆盖和未选择风险。

#### 退出门禁

- 至少一个关键切片从角色入口追到规则，并显式包含数据或异步副作用；实验、决策和验收具有可识别的后续占位。
- 每条业务结论都能回到证据项；断链不会被无类型“相关”链接掩盖。
- 静态证据只支持与其强度相符的状态，不把控制流可达性写成运行结果；未执行节点不得标为已完成或已确认。
- Phase 4 只通过追踪图骨架门禁，不得宣称最小追踪闭环已经完成；闭环要在后续验证、决定和验收均落地后才能完成。

#### 常见失败模式

- 追到一个保存函数就结束，遗漏事务提交后的队列、通知和汇总更新。
- 只寻找支持原假设的代码，不登记相反分支或失败处理。
- 为了画满闭环，把未知节点写成事实或复用不匹配版本的证据。

#### 停止规则

链路进入授权外资产或需要产生未隔离副作用时立即停止该方向；证据不足时以缺口结束切片，不允许用推断伪造闭环。

### Phase 5

**阶段目标：运行时实验。** 优先在隔离、可恢复的环境中验证关键行为与替代解释；无运行授权或无法安全运行时，走受治理的静态分支并显式保留限制。

#### 进入条件

- `ART-P4-TRACE` 给出了可证伪主张、前置状态、观测点和静态证据。
- 已选择运行分支或静态分支：运行分支要求环境、测试账号、合成或脱敏数据、副作用通道、成本上限和恢复方案均已批准；静态分支要求无运行条件及其影响可被审批。

#### 执行动作

1. 为每个实验写明主张、替代解释、版本、前置状态、输入、操作、预期、观测点、停止条件和清理核对。
2. 先执行最小只读或低副作用探针，再按批准范围覆盖正常、负向、逆向、重试和并发等高风险路径。
3. 同时采集用户可见结果、日志、调用、数据变化、消息、通知和时间信息，并保存首个失败而非用重试覆盖。
4. 重复关键实验、改变一个变量进行对照，将结果与静态链和领域陈述核对；只对实际运行支持的边界使用 `runtime-confirmed`。

##### 无运行授权的静态分支

只有以下原因可以选择静态分支，并须记录来源与批准人：授权未覆盖运行；合法环境不可用；依赖或硬件无法安全复现；副作用无法隔离。单纯为了节省时间、费用或跳过失败场景不构成理由；条件变化时应按重新打开规则评估运行分支。

- 建立**非运行验证记录 `ART-P5-STATIC`**：列出使用的源码、模式、配置、文档和领域证据，记录验证方法、工具版本、可复现步骤、交叉来源、反证和替代解释。
- 建立**运行证据缺口记录 `ART-P5-RUNTIME-GAP`**：逐条引用需要运行证据的主张，写明未运行原因、影响范围、剩余风险和允许的最高证据状态。必须依赖运行才能成立但没有运行证据的主张记为 `unsupported`；静态证据支持的另一条限定主张可标为 `statically-supported`、`inferred` 或 `conflicting`，但不得标为 `runtime-confirmed`。
- 对每项关键缺口记录风险接受人、接受理由、适用期限、重新打开条件和有权限的批准；在后续模型、审计、目的专用输出和发布说明中持续显示“未经运行确认”的限制。
- 当两份记录可复核、关键风险已由有权限的人限时接受、完成定义允许静态证据时，静态分支允许进入 Phase 6，并允许工作流继续完成；这不消除限制，也不构成运行行为证明。

#### 交付物

运行分支生成以下产物：

- **实验协议 `ART-P5-PROTOCOL`**：可复现步骤、变量、预期、风险和停止条件。
- **运行证据包 `ART-P5-RESULT`**：成功、失败、对照、工具版本和时间边界。
- **副作用核对单 `ART-P5-EFFECTS`**：写入、消息、通知、费用、清理和恢复结果。

静态分支生成以下产物：

- **非运行验证记录 `ART-P5-STATIC`**：静态分支的方法、来源、结果、反证和适用边界。
- **运行证据缺口记录 `ART-P5-RUNTIME-GAP`**：缺失运行证据的主张、状态限制、剩余风险和接受决定。

#### 退出门禁

- **运行分支：**关键实验可由另一执行者按协议复现，用户可见结果与后台副作用均已核对，失败样本和冲突没有被丢弃。
- **静态分支：**`ART-P5-STATIC` 与 `ART-P5-RUNTIME-GAP` 完整，所有必须依赖运行的主张保持 `unsupported`，剩余风险由有权限的人按期限接受，发布限制和重新打开条件可追踪。
- 两个分支的结论都限定到实际版本、角色、配置、数据和时间窗；只有运行分支中被实际结果支持的主张可使用 `runtime-confirmed`。

#### 常见失败模式

- 只截取成功界面，不核对事务、队列或通知是否完成。
- 自动重试覆盖首次失败，使错误和补偿语义不可见。
- 在共享或生产环境运行未设成本上限、停止条件的批量场景。
- 把“环境暂时不可用”写成永久免责，既不记录静态验证方法，也不让风险接受人复核。

#### 停止规则

出现真实用户影响、越权数据、意外外发、不可控费用、无法恢复写入或环境偏离基线时立即中止运行；保留最小现场证据并按 `ART-P0-STOP` 披露和恢复。运行不再安全或不再获授权时，仅在静态分支条件获批后转入该分支，不必让整个工作流停滞。

### Phase 6

**阶段目标：业务语义综合。** 把产品地图、纵向链和实验综合成能力、旅程、状态、规则与关键语义模型。

#### 进入条件

- 至少一个关键切片完成 Phase 4；运行分支已有 Phase 5 结果，或静态分支已有 `ART-P5-STATIC`、`ART-P5-RUNTIME-GAP` 和有效的风险接受记录。
- 产品主张与证据项采用[证据与置信度](evidence-and-confidence.md)的状态和链接约定。

#### 执行动作

1. 按[产品与业务建模](product-and-business-modeling.md)先校正产品地图，再编写能力、角色、旅程和交互模型。
2. 为正常、负向、逆向、重试、部分成功、批量和权限路径建立状态转换、守卫条件、副作用、错误和补偿。
3. 将规则分别写成自然语言、公式或决策表、正反例、适用边界和证据，明确金额、数量、时间、身份、租户、可见性、历史与删除语义。
4. 跨能力核对共享身份、守恒关系、生命周期和权限，记录跨模块不变量及可接受例外。

#### 交付物

- **产品模型包 `ART-P6-PRODUCT`**：产品地图、能力、角色、旅程、交互和场景矩阵。
- **行为模型包 `ART-P6-BEHAVIOR`**：状态机、规则、决策表、公式、权限、错误与补偿。
- **语义与不变量册 `ART-P6-SEMANTICS`**：关键语义、跨模块约束、例外和证据。

#### 退出门禁

- 模型以业务对象和行为组织，并能追到产品表面与技术资产；不存在以文件清单代替产品叙事的部分。
- 每条规则和不变量有适用边界、主张状态、置信度与证据，冲突内容没有被强行合并。
- 路径矩阵覆盖关键反向与部分成功行为，而不只描述正常流程。

#### 常见失败模式

- 从类名、表名或注释直接生成业务规则，没有运行或领域证据。
- 用一张理想流程图吞掉状态守卫、错误、权限和补偿。
- 将历史缺陷当成必须保留的需求，或因认定为缺陷而删除事实证据。

#### 停止规则

同一术语无法确定对象身份、关键规则仍有未解释冲突，或模型要求跨越批准范围时停止发布综合结论；拆分主张、降低置信度或回到 Phase 2–5 定向取证。

### Phase 7

**阶段目标：完整性、冲突与质量审计。** 对照冻结分母审查覆盖、证据链、冲突、版本边界和剩余不确定性。

#### 进入条件

- Phase 1 的分母与覆盖算法仍可复算，Phase 4–6 的对象和链接已有稳定 ID。
- 交付候选已声明目标决策、关键风险层和允许计入覆盖的状态。

#### 执行动作

1. 分别计算整体与关键层覆盖率，核对所有排除、范围变更和仅有空记录的项目。
2. 抽查产品表面到主张、证据、模型和验收的双向链接，验证版本、角色、租户、配置和时间边界一致。
3. 汇总 `conflicting`、`unsupported`、反证、失败实验和断链；为每项指定解决、隔离、降级或接受路径。
4. 由未编写该主张的人复核高风险样本，并审查敏感数据、保留期限、链接完整性、语言质量和机器校验结果。

#### 交付物

- **完整性审计报告 `ART-P7-AUDIT`**：覆盖率、抽样方法、断链、版本混用和质量问题。
- **冲突处置簿 `ART-P7-CONFLICT`**：相互竞争的主张、证据、决定人和重新打开条件。
- **已接受不确定性清单 `ART-P7-UNCERTAINTY`**：影响、处置、权限、期限和责任人。

#### 退出门禁

- 整体与关键项覆盖率达到已批准门槛，所有数字都能回到当前分母快照。
- 高风险断链和冲突已解决，或由有权限的人限时接受；没有默认接受的不确定性。
- 本地链接、文档结构、敏感信息检查和独立抽样审查均通过。

#### 常见失败模式

- 调整分母来满足目标，却不记录范围变更和重新批准。
- 把 `unsupported` 解释为“不存在”，把一次 `failed` 解释为永久不可用。
- 只执行格式校验，便宣称产品主张已经验证。

#### 停止规则

发现分母被静默修改、关键证据无法定位、敏感信息泄露或审计者缺乏必要独立性时停止发布；修复后重新计算覆盖并重做受影响抽样。

### Phase 8

**阶段目标：冻结与目的映射。** 冻结可复核证据版本，并按 Phase 0 的主要目的生成专用映射，防止事实观察自动升级为需求、迁移方案、选型结论、交易判断或竞争战略。

#### 进入条件

- `ART-P7-AUDIT` 已通过退出门禁，冲突和接受的不确定性具有有效责任人。
- 本次交付已从 `rewrite`、`migration`、`replacement`、`acquisition due diligence`、`competitor research` 中确定一个主要目的；若保留次要目的，每类输出另有范围、使用者和决策人。

#### 执行动作

1. 冻结证据目录、对象 ID、版本边界、主张状态、置信度和内容身份，生成可复核发布快照。
2. 选择下方目的专用映射，将事实主张与目标决定、责任人、完成条件和验收或接受记录分开。
3. 对每个已选目的核对关键范围项、静态分支限制、冲突和已接受不确定性，生成独立交付物。
4. 同一证据服务多个目的时分别创建类型化决策链接；后续决定不能继承事实主张的状态与置信度。

#### 目的专用映射与交付

| 主要目的 | 目的专用映射 | 命名交付物 | 完成条件 |
| --- | --- | --- | --- |
| `rewrite` | 旧行为与目标需求分离，逐项决定保留、纠正、有意舍弃或继续研究，并链接验收 | 重写决策映射 `ART-P8-REWRITE` | 关键行为均有批准决定、迁移影响和可执行验收；历史缺陷没有被无意固化 |
| `migration` | 源身份、字段、状态、历史和进行中业务映射到目标，说明转换、核对、切换、共存和回退 | 迁移连续性映射 `ART-P8-MIGRATION` | 范围内数据与状态都有转换和核对规则；关键例外、切换门槛与回退责任已批准 |
| `replacement` | 所需能力、场景、数据、集成和非功能门槛映射到候选产品的适配、差距、变通和退出成本 | 替换适配矩阵 `ART-P8-REPLACEMENT` | 关键能力以行为证据完成适配判断；差距、变通、转换成本和退出条件已被接受或阻断决定 |
| `acquisition due diligence` | 有时限的产品、技术、数据、依赖、权利和运营事实映射到估值、条款、整合与风险问题 | 收购尽调风险映射 `ART-P8-DUE-DILIGENCE` | 重大风险、证据缺口、权利边界、影响和交易责任人均已披露；逆向团队不代替交易决策 |
| `competitor research` | 同版本、套餐、角色、地区和时间边界下比较能力与旅程，分开观察、解释假设和战略问题 | 竞品比较映射 `ART-P8-COMPETITOR` | 可比项均有合法来源和一致边界；证据缺口、替代解释与战略决定人明确 |

#### 交付物

- **证据冻结清单 `ART-P8-FREEZE`**：范围、内容身份、生成时间、保管人和后续增量规则。
- **目的专用映射**：为每个已选目的生成上表对应的命名交付物，次要目的不得复用主要目的的完成判定。
- **发布说明 `ART-P8-RELEASE`**：可用于和不可用于的决策、已接受不确定性及复核日期。

#### 退出门禁

- 冻结快照可重建，后续编辑不会静默改写本次交付使用的证据。
- 每个已选主要目的及次要目的都满足上表对应的完成条件，并拥有独立对象类型、责任人、批准或风险接受记录和追踪链接。
- 事实与重写需求、迁移方案、替换判断、交易影响、竞品解释及战略决定保持分离；静态分支限制持续显示。
- **完整闭环门禁：**只有角色/入口、交互、代码/服务、数据/异步副作用、规则、实验或静态替代验证、目的决定和验收或风险接受均落地并可追踪，才可宣称相应关键项完成最小追踪闭环。

#### 常见失败模式

- 把重写模板套到所有目的，导致迁移连续性、候选适配或交易权利风险没有专用完成条件。
- 直接复制旧行为作为新需求，或把竞品功能名称写成能力等价和市场优劣结论。
- 用高置信度事实替代迁移、采购、交易或战略负责人的决定。
- 冻结后继续原地修改证据，导致评审者无法复现当时决定。

#### 停止规则

缺少目的专用决策权限、证据快照不可重建、完成条件未满足，或观察与决定对象无法区分时停止发布对应映射；其他目的不能替它通过，先补齐授权、决定和冻结身份。

### Phase 9

**阶段目标：增量校准与方法学习。** 用新版本、新证据和已知结果校准主张与方法，控制全量重做成本并沉淀可复用经验。

#### 进入条件

- 存在通过 Phase 8 的冻结基线、范围分母、证据目录和发布说明。
- 新版本、新证据、决策结果或抽样复核具有明确来源和比较边界。

#### 执行动作

1. 比较版本、配置、模式、产品表面和证据内容身份，先确定受影响对象和链接，再安排定向复查。
2. 对受影响的纵向切片与验收场景重跑最小集合，更新主张为 `deprecated`、`superseded`、`conflicting` 或新的适当状态。
3. 记录方法曾预测什么、实际结果是什么、误判与漏判来自何处，用抽样数据校准取证顺序和停止门槛。
4. 将项目经验登记为方法学习候选；只有满足独立证据要求时，才按贡献规范申请提升成熟度或提炼 Pattern、Anti-pattern、Experiment。

#### 交付物

- **增量影响报告 `ART-P9-DELTA`**：基线、新证据、受影响对象、重跑集合和未影响理由。
- **校准记分卡 `ART-P9-CALIBRATION`**：预测、结果、误判、漏判、样本边界和方法调整。
- **方法学习日志 `ART-P9-LEARNING`**：可复用经验、反例、证据范围和提炼候选。

#### 退出门禁

- 所有受影响关键项已重验或形成有权限、有限期的已接受不确定性。
- 旧主张通过取代或弃用关系保留历史，未把不同版本证据拼成无边界结论。
- 方法成熟度只依据独立项目或权威来源证据调整，不因文档完整或单次成功自动晋升。

#### 常见失败模式

- 新版本一发布就全量重做，没有先用追踪关系缩小影响范围。
- 覆盖率保持不变便认为语义未变，忽略同一入口背后的规则或副作用变化。
- 把项目内重复运行误称为跨项目验证，混淆主张置信度与方法成熟度。

#### 停止规则

没有可验证的冻结基线、比较对象混用版本、或新证据来源不明时停止增量结论；重新建立基线或隔离材料后再校准，不能凭记忆覆盖历史记录。

## 阶段回退与有限并行

阶段门禁不是单向瀑布。Phase 4–7 发现新入口、对象或版本时，先登记范围变更，再回到相应阶段更新分母和证据；受影响项重新过门禁，未受影响项保留原证据身份。团队可以并行处理不同切片，但 Phase 0 的授权、Phase 1 的分母规则和共享对象 ID 是共同前置条件。

工作停止不等于任务失败。停止记录应说明触发器、已完成的安全动作、受影响范围、当前主张状态、恢复授权人和重新进入条件，使后续人员可以从证据而非口头记忆继续。
