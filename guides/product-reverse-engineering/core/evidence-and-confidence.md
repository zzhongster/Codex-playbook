# 证据与置信度

**证据成熟度：`proposed`**

**适用范围：** 适用于登记获授权的产品逆向证据、表达可审查主张并建立跨界面、代码、数据、运行行为和领域解释的追踪关系；不把文档结构校验当作事实验证。

文档头部的“证据成熟度”是“本指南方法或建议的支撑证据成熟度”的机器可读简称。四个标签只描述逆向工程方法或建议的支撑证据成熟度，不描述目标产品主张的真假。目标产品主张使用主张状态、置信度和证据引用表达可信程度。

## 四个独立轴

证据模型必须把以下四个概念分开，并用引用连接各自记录，而不是把四个字段强塞进每条产品主张。来源强不保证主张正确，主张已确认不保证某个方法跨项目成熟，高置信度也不能把静态分析改写成运行时事实。

| 轴 | 回答的问题 | 不应混入的内容 |
| --- | --- | --- |
| 证据与来源类型 | “依据是什么，来自哪里、哪个版本和时间？” | 对业务含义的最终判断 |
| 主张状态 | “这句话目前被何种证据支持，是否冲突或失效？” | 评审者的主观把握程度 |
| 置信度 | “在现有证据和边界内，我们有多大把握？” | 工作流是否已跨项目验证 |
| 方法成熟度 | “本指南采用或推荐的方法在多大范围被验证？” | 单条产品主张是真是假，或主张的整体属性 |

## 证据与来源类型

证据项是带来源身份、版本、采集方法、时间、保管与完整性信息的可复核材料。建议至少区分：

| 类型 | 例子 | 能直接支持什么 | 主要限制 |
| --- | --- | --- | --- |
| `runtime` | 隔离环境中的操作记录、事件、日志、调用与数据变化 | 指定版本、配置、账号和场景下实际发生的行为 | 单一场景不能自动推广到其他角色、配置或失败路径 |
| `static` | 源码、二进制结构、数据库模式、配置、部署描述 | 可达路径、声明结构、约束和实现候选 | 不证明路径在运行时被触发，也不证明业务意图 |
| `interface` | 页面、API 描述、报表、导入导出格式 | 用户或集成可见的结构、措辞与交互 | 可见结构不一定等于内部语义或所有权限状态 |
| `documentary` | 手册、规范、发布说明、合同化接口说明 | 声明的设计、责任和版本变化 | 可能滞后于实现，必须核对适用版本 |
| `domain` | 领域负责人确认、受控访谈、业务规则评审 | 业务意图、术语、例外和风险解释 | 记忆或组织实践可能与实际产品行为不同 |
| `derived` | 查询结果、反编译输出、图谱、聚合指标 | 从已登记输入按记录方法得到的派生事实 | 必须保留输入链接、工具版本、参数和可重复步骤 |

证据项不直接等于主张。一个证据可以支持多个主张；一个主张通常需要多个独立证据。原始材料不可提交时，至少保存受控位置的引用、内容哈希、可用期限和访问责任方。

## 主张状态

状态描述主张当前与证据的关系。每个主张保留一个当前状态和状态历史；状态变化必须记录触发证据与评审人。

| 状态 | 定义 |
| --- | --- |
| `observed` | 在明确版本、时间和上下文中直接看见或读取到的事实，尚未越过记录内容解释其原因或普遍语义 |
| `statically-supported` | 源码、模式、配置或二进制静态结构支持该主张，但相关路径没有得到运行时执行确认 |
| `runtime-confirmed` | 在批准且可重复的运行场景中确认行为，并记录输入、环境、结果和副作用；只对已测边界成立 |
| `domain-confirmed` | 有权限的领域负责人确认业务意图或规则；若实现行为不同，必须进入冲突处理而不是覆盖运行证据 |
| `inferred` | 由一个或多个证据推导出的最佳解释，推理步骤、替代解释和验证缺口均已显式记录 |
| `conflicting` | 两个或更多适用证据或有效确认无法同时成立，尚未完成版本、上下文或权威性消解 |
| `unsupported` | 当前没有足够证据支持主张，或已有证据不足以达到目标决策所需门槛；它不是“主张为假”的证明 |
| `deprecated` | 主张对历史范围曾有效，但已明确不建议用于当前范围；保留它用于历史解释并链接替代项（如有） |
| `superseded` | 一个更新且经评审的主张明确取代本主张；旧记录保持可寻址并以类型化关系指向新记录 |

`observed` 不应被用作“已理解语义”的快捷标签；`statically-supported` 不应被写成 `runtime-confirmed`。领域确认与运行确认回答不同问题，任何一方都不能静默覆盖另一方。

## 冲突与取代

出现矛盾时把主张置为 `conflicting`，并分别保留支持与反驳证据。先检查版本、配置、角色、数据、时间和环境是否不同；能按边界拆分的主张创建各自限定的新主张，不能拆分的交由指定权威人裁决。裁决记录不得删除少数证据。

取代不是编辑旧结论。新建主张，给旧主张标记 `superseded`，添加 `replaces` 追踪链接，并记录适用版本、理由和批准人。仍有历史解释价值但没有单一替代项时使用 `deprecated`；不要滥用 `superseded` 隐藏冲突。

没有发现证据不等于证明其不存在。声称“没有某功能、规则、写入或集成”时，必须定义被搜索的分母、版本、路径、权限和方法，并将结论限定为“在这些边界内未发现”；否则状态使用 `unsupported` 或 `inferred`。

## 置信度

置信度是对单条主张在声明边界内可靠程度的评估，建议使用 `low`、`medium`、`high`，同时写明理由而不是只给分数。

| 级别 | 建议判据 |
| --- | --- |
| `low` | 证据单一、来源间接、版本不确定、替代解释较多，或关键反证路径未检查 |
| `medium` | 至少有可复核的直接证据，关键边界明确，但仍缺独立来源、失败路径或范围代表性 |
| `high` | 多个独立且适用的证据相互印证，关键反证已测试，版本与上下文稳定，复核可重复 |

状态和置信度必须分别填写：可有高置信度的 `statically-supported` 主张，也可有低置信度的 `runtime-confirmed` 主张（例如场景不稳定或样本过小）。冲突未消解时，不因投票数量直接给高置信度。

## 方法成熟度

方法成熟度沿用贡献规范中的 `proposed`、`project-validated`、`industry-established`、`cross-project-validated`。它评价本指南采用或推荐的采集、追踪、推断或验证方法背后的支撑证据广度，不评价某条产品主张本身。

方法在一个项目成功只支持 `project-validated`；行业资料支持的方法可标为 `industry-established`，但仍需说明本地版本和边界；只有至少两个相互独立项目的可追溯验证才能达到 `cross-project-validated`。结构测试通过不会提升方法成熟度。

一个产品主张可以依赖多个成熟度不同的取证方法：每份证据分别引用产生它的方法及该方法的成熟度，产品主张只汇总证据引用，并以主张状态和置信度表达判断。即使所有证据来自同一种方法，产品主张也不携带一个整体的方法成熟度；方法变更或新增证据时，只更新相应方法与证据关系。

## 身份与追踪

### 限定稳定 ID

每个证据项、主张、产品表面、技术资产、业务能力、数据对象和集成对象都使用限定稳定 ID。推荐结构为 `对象类型:命名空间.稳定键`，例如 `claim:orders.cancel-rule`；显示名称、文件路径和数据库名称不得代替身份。

稳定 ID 一经发布不因改名、移动或版本变化复用给其他对象。版本、环境和角色作为对象限定字段或主张边界记录；只有语义身份真正变化时才创建新 ID，并建立关系。

### 别名与墓碑

别名把历史名称、界面名称、代码符号或外部编号解析到一个规范 ID。别名必须有命名空间、有效时间和来源，不能让同一上下文中的一个别名静默指向多个对象。

对象删除、合并或无法继续引用时保留墓碑：原 ID、最后已知类型、失效原因、时间和替代 ID（如有）。墓碑禁止 ID 被重新分配，也让旧证据链保持可解释。

### 类型化追踪链接

追踪链接不是无语义的“相关”。每条链接包含源 ID、关系类型、目标 ID、适用版本/上下文、证据 ID 和当前状态。关系类型至少按用途区分：

| 关系 | 含义 |
| --- | --- |
| `supports` / `contradicts` | 证据支持或反驳主张 |
| `exposes` / `implements` | 产品表面暴露能力，或技术资产实现能力/主张 |
| `reads` / `writes` | 行为或资产读取、写入某数据对象 |
| `calls` / `emits` | 组件调用集成端点或发出事件 |
| `derived-from` | 派生证据或主张来自哪些已登记输入 |
| `validates` | 场景、测试或领域评审验证主张 |
| `replaces` | 新主张或对象明确取代旧项 |

链接本身也是可审查主张。若只知道两个对象可能有关，记录为带 `inferred` 状态的候选链接，不要提前赋予 `implements` 等确定语义。

## 最小主张记录

一条可发布主张至少包含：稳定 ID、精确句子、适用版本/角色/场景、当前状态、置信度及理由、支持与反驳证据链接、创建与复核人、时间，以及冲突、别名、墓碑或取代关系（如适用）。每份证据可另行引用其取证方法和该方法的成熟度。
