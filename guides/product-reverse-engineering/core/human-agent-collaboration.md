# 人机协作

**证据成熟度：`proposed`**

**适用范围：** 适用于由产品/领域人员、逆向工程人员、QA、安全/隐私人员和 AI Agent 共同处理已获授权的产品逆向任务；不适用于把授权、领域裁决、风险接受、破坏性实验批准或发布冻结委托给 AI，也不因自动化效率扩大任务范围。

协作的基本单位是带输入身份和停止条件的任务包，而不是一句宽泛提示。人类保留目的、风险和发布决定，AI Agent 在任务包内检索、转换、关联、校验和起草；所有输出沿用[证据与置信度](evidence-and-confidence.md)的对象、状态与类型化链接。

## 决策权矩阵

一项工作可以多人执行，但每个决定只能有明确的最终责任角色。代理、请假替代或职责合并必须书面记录授权范围和有效期；职责分离要求高于进度便利。

| 角色 | 决策权与责任 |
| --- | --- |
| 产品/领域负责人 | 决定业务目的、术语与意图、关键规则、历史行为是否成为目标需求，以及业务不确定性是否可接受；不覆盖安全否决 |
| 逆向负责人 | 维护范围、分母、切片顺序、证据链和方法一致性，协调冲突与门禁；不能代替业务、安全或交易最终决定 |
| 技术分析师 | 定位代码、制品、配置、数据与集成，提出技术主张、替代解释和复现步骤；不从实现命名直接裁决业务语义 |
| 产品研究员 | 建立角色、产品表面、旅程、能力和比较边界，区分观察、解释与战略问题；不把竞品观察升级为战略结论 |
| QA/实验负责人 | 审核实验协议、预期/实际、路径分母、首错、复现和清理结果，判定实验记录是否满足质量门槛；不批准超出授权的运行 |
| 安全/隐私负责人 | 决定数据类别、最小化、测试账号/克隆、采集与外发边界、破坏性或故障实验条件、停止/披露/处置要求，并可否决不安全活动 |
| AI Agent | 在任务包允许范围内检索、提取、关联、生成候选主张和运行确定性校验，显式报告证据缺口；没有授权扩张、业务裁决、风险接受或冻结批准权 |

涉及采购、法律、交易或运营的最终责任未出现在表中时，应由组织另行指定有权限的评审人；逆向负责人不得默认为代理人。

## 任务包契约

任务开始前由分派人与 `review owner` 共同确认以下**恰好十三项必填字段**。字段内容作为执行边界；任何会改变目的、授权、输入、工作目录、范围、证据权限、输出位置或风险的变化都生成新版任务包，并保留旧版身份。

| 字段 | 必填内容 |
| --- | --- |
| `objective` | 一个可判定的问题、服务的决策用途与完成结果 |
| `authorization record ID + content hash/version` | `ART-P0-AUTH` 的稳定 ID、内容哈希/版本，以及证明它已通过当前 G0 的 `ART-G0-AUTH` 派生判定记录 ID 与哈希 |
| `input identity` | 仓库提交、文件/证据哈希、产品构建、环境/克隆、配置、账号角色和时间窗的不可变身份 |
| `workspace root / working directory identity` | 工作区根的稳定身份、仓库/工作树版本，以及相对该根的规范工作目录；相对输入、输出和验证命令都从此处解析 |
| `scope` | 包含、排除、版本、角色、产品表面、资产、数据、集成和非功能边界 |
| `denominator` | 预先枚举的范围项稳定 ID、父子结构、P0/P1/P2、目标状态与计算规则 |
| `allowed evidence` | 授权记录允许集合内、任务实际可以读取、复制、运行、查询或派生的来源、数据级别、工具与动作 |
| `forbidden inference` | 不得从命名、静态可达、聚合结果、行业常识、未找到或历史输出推出的结论 |
| `output paths or record types` | 允许写入的相对路径、对象类型、文件类型和输出允许列表 |
| `schema` | 产物字段、稳定 ID、关系、枚举、模式版本和序列化约束 |
| `validation command` | 可从已声明工作目录执行的精确命令、工具版本和预期退出条件 |
| `stop conditions` | 越权、敏感信息、真实用户影响、环境漂移、不可恢复写入、冲突或输入缺失等停止触发器 |
| `review owner` | 有权接受产物、处理冲突和决定重新执行或升级的具体人类角色/责任人 |

任务包通过不可变 `authorization record ID + content hash/version` 绑定 `ART-P0-AUTH`，并引用 `ART-G0-AUTH` 的当前 `pass` 判定；`allowed evidence` 必须是该授权记录的子集。范围负责人、分派人和评审人都无权扩大该集合。任何证据来源、数据、动作、账号、环境或时间边界扩张，都必须先由有权限的人类重新授权，创建新的授权记录并使 G0 再次 `pass`，之后才能创建新的任务包；不得修改旧任务包就继续执行。

`workspace root / working directory identity` 是路径解析锚点。任务包内的相对输入、`output paths or record types` 与 `validation command` 必须在该工作目录解析；根身份、仓库/工作树版本或工作目录变化都会使当前任务包失效并要求新版，而不能依赖执行者当前 shell 或个人目录猜测。

未给出的信息保持未知，不由 AI 或执行者填入“合理默认”。若缺少字段但仍可进行不触及缺口的只读准备，产物必须标记为草案；到达依赖该字段的动作时停止并向 `review owner` 请求决定。

## 分派、执行与交接

分派人将任务包绑定到一个冻结输入版本和唯一任务 ID。执行者先回报理解的目标、输入身份和停止条件，再只在 `output paths or record types` 中写入；发现新对象先进入候选/未知队列，不自行扩张分母。并行任务共享稳定 ID 注册表，但各自保留证据来源和写入所有权，避免两个执行者静默覆盖同一结论。

交接包包含任务包版本、已完成分母项、未完成/未知项、支持与反驳证据、运行和清理状态、输出清单与哈希、验证结果、偏差以及需要谁决定什么。接收人从输入身份和验证命令复核，不以对话摘要代替证据；未复核输出保持候选状态。

出现证据冲突时，执行者不得“取多数”或选择最方便版本。分别保留主张、版本、上下文和证据，把当前主张设为 `conflicting`，由逆向负责人组织相应产品/领域、技术、QA 或安全责任人决定拆分边界、继续取证、限时接受或停止发布。

## AI Agent 能力边界

AI Agent 适合做有明确输入与模式的检索、去重、候选映射、表格/图谱生成、静态追踪、实验协议草拟、确定性校验和缺口汇总。它必须为输出列出输入身份、方法、证据引用、推断步骤、替代解释、限制与验证结果，不能把语言流畅度当作置信度。

AI Agent **可以报告“未找到”**，并附已搜索的分母、版本、路径、查询和权限；但**不能据此推断不存在**。它可以提出业务规则、能力、缺陷、需求或风险候选，但**不能作出业务最终决定**，也不能接受不确定性、降低风险级别、批准越权/破坏性操作或签署冻结。

静态代码、界面文字、聚合查询和基础设施可达性不能被 AI 合并为运行时行为。没有获准且可复现的运行证据时，需要运行才能成立的主张保持 `unsupported`；存在静态支持时另建边界准确的 `statically-supported` 或 `inferred` 主张。模型间一致、生成测试通过或重复同一提示不构成独立产品证据。

Agent 发现凭据、个人数据、跨租户内容、可利用漏洞、真实用户影响或意外写入时，应按任务包停止条件停止相关动作，保存最小且脱敏的现场引用，并交给安全/隐私负责人规定的披露路径，不继续探索以“确认影响”。

## 人工确认与发布责任

以下事项必须由具备相应权限的人类明确确认，并在证据或决定记录中签名：

| 确认事项 | 最终责任 |
| --- | --- |
| 高风险规则 | 产品/领域负责人确认业务意图、适用边界、例外和用于目标决策的方式；QA 核对可测试性 |
| 证据冲突 | 相应领域/技术责任人确认版本或上下文拆分、继续取证或保留冲突；不得删除少数证据 |
| 安全边界 | 安全/隐私负责人确认账号、数据、环境、采集、外发、保留、停止和披露条件 |
| 破坏性实验 | 安全/隐私与系统责任人共同批准隔离、爆炸半径、恢复点、成本、停止开关和处置；AI 只可草拟协议 |
| 冻结 | 逆向负责人、目的决策人和 `review owner` 核对分母、P0/P1、未知、证据身份、输出哈希、限制与用途后签署发布 |

高风险规则即使有一致的运行与静态证据，仍需产品/领域人员确认业务意图；实现事实不能代替“应当如何”的决定。安全负责人可以否决实验，产品负责人不能以业务紧急覆盖授权或隐私边界。冻结签名证明特定输入和交付获准发布，不表示所有未知消失，也不提高方法成熟度。

人工确认分别固化为不可变决定产物：G0 使用 `ART-P0-AUTH`，非运行分支使用 `ART-P5-STATIC-ACCEPTANCE`，审计风险接受使用 `ART-P7-ACCEPTANCE`，发布批准使用 `ART-P8-APPROVAL`。签署人直接决定适用范围、时间、理由和签名；`ART-G*` 门禁生成器只按固定规则验证这些输入及其哈希，不能替人生成或修改决定。

## 复核升级与停止

`review owner` 按任务包抽查证据、重跑验证并处理偏差；涉及其他决策权时升级到对应角色。验证失败、输入哈希变化、范围外依赖、关键证据缺失、P0/P1 未解决/未被有权者接受，或非运行限制从输出中消失时，不得接受任务包或冻结。

停止后保留任务包、最后已知安全状态、已生成证据、未清理副作用、披露对象和恢复条件。恢复需要新的或重新确认的授权与输入身份；不能让另一个 Agent 在旧上下文上自动续跑。
