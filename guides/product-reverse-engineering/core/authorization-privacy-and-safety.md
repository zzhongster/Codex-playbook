# 授权、隐私与安全

**证据成熟度：`proposed`**

**适用范围：** 适用于对已获授权的软件、账号、环境、数据和文档开展静态或运行时逆向工程；遇到授权歧义、受监管数据或可能影响真实用户的操作时，由相应负责人决定能否继续。

## G0 授权检查清单

G0 是任何采集、运行、抓包、导出、反编译或自动化之前的硬门禁。所有选项必须有明确答案和责任人；“技术上可访问”不等于“已授权”。

- [ ] 业务目的、主要决策和预期交付物已经书面批准。
- [ ] 系统、产品版本、组织/租户、账号、环境、时间窗和地域边界已经列明。
- [ ] 允许读取、复制、执行、修改、监测和导出的动作分别获得授权；未列明的动作视为不允许。
- [ ] 证据来源、数据类别、敏感级别、跨境限制和第三方权利已经评审。
- [ ] 测试账号、隔离环境、速率限制、副作用、停止条件和恢复负责人已经确认。
- [ ] 安全克隆、存储位置、访问名单、脱敏方式、保留期限和删除证明已经确认。
- [ ] 异常发现、个人数据、漏洞、凭据暴露和越界迹象的披露路径已经确认。
- [ ] 任务负责人和授权人完成签署；授权变更、到期或撤销会立即停止相关活动。

任一项不明确时，只能进行不触及该不明确边界的工作。新版本、新租户、新数据类别或新测试动作都需要重新过 G0，不能沿用“类似环境”的授权。

## 允许的证据来源

来源必须同时满足任务授权、合同/许可证和数据处理规则。常见允许来源包括：

| 来源 | 最低条件 |
| --- | --- |
| 产品文档、用户手册、发布说明 | 公开发布或组织已合法取得，并记录版本与获取时间 |
| 经批准的源码、二进制、配置和构建产物 | 明确拥有读取/分析权；第三方组件按各自权利边界处理 |
| 隔离环境中的界面、日志、网络和性能记录 | 使用批准场景、账号与采集范围；不夹带无关用户或租户数据 |
| 脱敏数据库快照、模式和样例导出 | 数据所有者批准，字段级最小化，导出与销毁可审计 |
| 领域访谈、支持工单和既有测试 | 参与者知情，访问范围合规，主观陈述与运行证据分开登记 |
| 公开可访问的竞品材料 | 遵守适用条款和速率边界，不把偶然暴露的非公开信息当作许可 |

没有来源信息、权利状态或版本边界的材料先隔离，不进入正式证据链。

## 数据最小化与脱敏

只收集支持已批准主张所需的最小字段、最短时间窗和最少记录数。能用合成数据回答的问题不使用真实数据；能在源端聚合或筛选的内容不整库导出。

脱敏要按用途选择删除、掩码、泛化、标记化或不可逆哈希，并保留字段语义与关联需求。密钥、会话令牌、口令、支付凭据和恢复码不得进入证据库。个人信息、客户内容和商业秘密在截图、日志、SQL 输出、提交历史与评审消息中使用一致的脱敏规则。

每份证据记录原始敏感级别、处理方式、可访问角色和复识别风险。脱敏后的材料仍按剩余风险管理，不能因为替换了姓名就自动视为公开信息。

## 测试账号隔离

运行时验证使用专用测试账号、独立测试组织/租户和可识别的合成数据。账号采用最小权限，并与个人账号、管理员账号、生产集成凭据分离。

为每个场景预设速率上限、费用上限、可写资源、通知抑制范围和停止条件。邮件、短信、支付、物流、Webhook 等外部副作用使用沙箱或受控接收端；无法隔离的副作用必须在执行前单独批准。

测试结束后撤销临时凭据、令牌和授权，清理测试数据并核对没有影响其他租户或真实用户。共享账号会破坏责任归属，不作为默认方案。

## 安全克隆

对源码、数据库、虚拟机或文件系统制作安全克隆时：

1. 在源端确认版本、快照时点、所有者、授权范围和预期内容哈希。
2. 优先生成只读、离线或网络受限的副本；移除生产凭据、自动任务、外发通道和真实服务地址。
3. 在受控位置解密和脱敏，使用独立密钥与最小访问名单，不把敏感副本放入普通 Git 历史。
4. 记录源身份、克隆身份、工具版本、内容哈希、过滤规则和保管人，使证据可复核而不暴露敏感值。
5. 首次启动前检查定时任务、消息消费者、支付/通知集成和写回路径；确认恢复与紧急停止机制。

“克隆”不改变数据权利或许可证边界。快照可回滚也不代表允许执行破坏性试验。

## 保留与删除

每类证据在采集前设定保留期限、法律保留例外、存储区域、访问角色和到期处置。原始敏感证据与脱敏派生物分别登记；派生物不能自动继承更长保留期。

到期后按批准方式删除所有工作副本、缓存、临时导出和共享链接，并保留不含敏感内容的删除证明。若因审计、诉讼保全或安全事件暂停删除，记录决定人、范围和复核日期。项目结束不等于可以无限期保存材料。

## 披露路径

发现疑似漏洞、未预期的个人数据、第三方秘密、许可证冲突、越权能力或生产影响时：

1. 立即停止会扩大影响的动作，保留最小现场信息，不继续验证可利用程度。
2. 通过预先指定的安全、隐私、法务、数据所有者或产品负责人渠道报告；按事件类型限制知情范围。
3. 记录发现时间、环境、最小复现、潜在影响和已采取的遏制措施，敏感值另行受控传递。
4. 由有权限的负责人决定修复、通知、进一步测试与外部披露；逆向团队不自行公开。

披露记录与普通研究笔记分离，避免漏洞细节或个人数据通过常规交付物扩散。

## 禁止事项

以下动作明确不属于本指南允许的逆向工程，即使它们可能获得更多信息：

- 凭据窃取、钓鱼、会话劫持，或使用偶然发现但未获授权的凭据；
- 许可证破解，移除或伪造许可证校验；
- 绕过访问控制、租户隔离、认证、授权或数据分级边界；
- 规避付费功能、配额、订阅限制或计费流程；
- 拒绝服务、资源耗尽、无批准的压力测试或会影响真实用户的探测；
- 未经批准的破坏性写入，包括删除、篡改、批量迁移或向生产系统写回；
- 隐蔽持久化、恶意代码投放、规避审计，或扩大到授权外的系统、账号、版本和数据。

压力、进度或“只读副本”都不能自动解除这些禁止事项。确有合法安全测试需求时，应进入独立、明确授权的安全评估流程，而不是扩大本指南的任务范围。
