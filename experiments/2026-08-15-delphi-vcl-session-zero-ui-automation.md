# 实验：在 Windows Session 0 自定义桌面自动化 Delphi 5/VCL

**日期**：2026-08-15
**项目**：管家婆 V8.8 遗留 ERP 黑盒逆向验证

## 目标

在没有持续 RDP 登录的远端 Windows Server 上，通过产品真实界面稳定回放 Delphi 5/VCL 业务流程，并用独立数据库断言区分“界面看起来成功”和“业务事件真正生效”。

## 环境与约束

- Windows Server 2025，2 核 / 4 GB。
- Delphi 5 VCL 客户端、COM/MIDAS 中间件、SQL Server 2000/MSDE 兼容数据库。
- 自动化进程由 SYSTEM 计划任务启动，目标桌面为 `winsta0\GJPLab`。
- 原始截图、窗口树、数据库阶段快照和日志保留在受控证据目录；Git 只保存脱敏索引和哈希。

## 竞争方案

| 方案 | 观测 | 结论 |
|---|---|---|
| 依赖活动 RDP 会话和默认桌面 | 会话断开或服务器重启后，客户端、窗口句柄和输入目标不可持续 | 不适合作为长流程无人值守基础 |
| Session 0 + 只寻找 `winlogon` token | 无交互登录时 Session 0 不存在目标 `winlogon`，启动器失败 | token 来源不能硬编码为 `winlogon` |
| Session 0 + SYSTEM 自身 token + 自定义桌面 keeper | 重启后可按固定顺序恢复中间件、Socket、桌面 keeper、客户端和回放器 | 可作为隔离的遗留 UI 实验底座 |

## 关键实现

1. 启动器先查目标 Session 的 `winlogon`；若不存在且调用进程本身就在目标 Session，则复制当前 SYSTEM token。
2. keeper 从默认桌面创建并持续持有 `winsta0\GJPLab`，客户端与自动化器全部显式启动到同一桌面。
3. 重启恢复顺序固定为：数据库服务 → 中间件/Socket → keeper → 客户端 → 登录回放。
4. 每个 UI 动作之后执行独立 32 位 ADO 查询，将数据库状态写成按阶段编号的 JSON；保存、审核、重载、反审核、删除分别断言。
5. 终态除业务关系和余额恢复外，还检查进程/计划任务清理、目录业务键、数据库 ONLINE 状态和 `DBCC CHECKDB`。

## Delphi/VCL 特殊交互

### MDI 同名隐藏按钮

多个单据窗体并存时，按类名和标题搜索可能命中较早创建但已隐藏的同名按钮。实验改用“类名 + 屏幕左上坐标”定位当前可见实例，并直接投递 `BM_CLICK`。坐标不是跨版本稳定标识，因此每次回放前必须用窗口树或截图重新确认。

### 自定义编辑器不回显标准窗口文本

部分 `TGjpEdit` 接受字符和提交事件，但标准 `GetWindowText` 始终返回 `0`。严格的“输入后窗口文本必须相等”会制造假失败。对此提供 raw 输入模式：仍发送真实字符与键盘提交事件，但把正确性判定交给后续界面状态和数据库断言。

### 日期显示值不等于业务状态

直接设置日期文本可能改变视觉值，却没有触发旧控件的 `OnChange`，最终编号日期或查询条件仍取旧值。可靠路径是聚焦实际日期控件，按字段分段输入，并通过保存后的编号、重载值和数据库日期共同验证。

## 数据

- 完成 53 阶段采购成本与结算边界状态机，53/53 个 `logical_state_passed=true`。
- 覆盖折后金额/价税合计分摊、按商品开票、来源退货、正负付款、未分配转预付/应付及完整逆向清理。
- 本轮新增 179 张界面截图；整个运行目录最终有 2,038 个普通证据文件。
- 完整性复核：路径差异 0、哈希不匹配 0；最终数据库 331 张用户表，`DBCC CHECKDB` 通过。
- 终态活动测试单据、发票、分摊/结算关系和会计副作用均为 0；identity、编号高水位和事件日志按历史语义保留增长。

## 结论

Session 0 自定义桌面可以稳定承载无人值守的旧 VCL 黑盒实验，但“成功”不能由点击返回值或截图单独判定。可靠的最小组合是：可见控件定位、真实输入事件、阶段化数据库断言、重载验证、逆序清理和终态完整性检查。

该方法目前只在一个遗留 ERP 项目验证，应暂存为实验；待在第二个 Win32/VCL 产品复现后，再提升为通用 Pattern。

## 可复用检查清单

- [ ] token 来源在无 `winlogon` 的目标 Session 仍可用。
- [ ] keeper、客户端和自动化器位于同一 window station/desktop。
- [ ] 多 MDI 场景不按第一个同名句柄盲点。
- [ ] 自定义编辑器由业务结果验证，不依赖标准窗口文本。
- [ ] 日期等有事件语义的控件通过真实键盘路径提交。
- [ ] 每个重要动作都有保存后、重载后和数据库三方证据。
- [ ] 阻塞分支同时证明界面提示和数据库零变化。
- [ ] 清理顺序按依赖逆序，终态区分业务恢复与 identity/缓存字节级回滚。
