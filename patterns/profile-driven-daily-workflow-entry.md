# Pattern: Profile-driven daily workflow entry

## 一句话结论

要把多功能 B2B 产品做成客户每天必须打开的入口，不要只做可配置菜单或拖拽 Dashboard；应先沉淀用户/企业 Profile，再由 Profile 驱动每日任务流，让系统每天告诉用户该做什么、为什么做、下一步怎么做。

## 适用场景

- 产品已有多个强功能模块，但用户需要自己判断先用哪个、怎么串起来。
- 客户的工作目标稳定重复，例如获客、背调、触达、跟进、复购。
- 不同用户的产品、市场、偏好、排除条件、权限和成熟度差异很大。
- 希望从“工具型产品”升级为“工作入口”或“业务操作系统”。

## 典型失败

团队把“千人千面”理解成首页模块自定义：

1. 用户自己拖拽常用功能卡片。
2. 系统按角色显示不同菜单。
3. 首页展示若干统计图和快捷入口。

这只能减少点击，不能改变工作方式。用户仍然要自己判断今天该找哪些客户、查哪些公司、联系谁、什么时候跟进。产品还是工具箱，不是工作入口。

## 正确结构

1. 先建 Profile：沉淀用户/企业的产品、目标市场、客户类型、排除条件、价格带、认证、历史开发记录、常用判断口径。
2. 把 Profile 注入所有核心工作流：搜索、推荐、背调、触达、CRM、提醒都默认应用这些约束。
3. 首页展示“今日任务”而不是“功能集合”：新增机会、待确认推荐、待触达联系人、待跟进邮件、风险提醒。
4. 工作流以模板启动，允许用户微调：例如“每周找 20 家北美进口商”“回复后自动生成跟进建议”“采购额增长超过阈值时提醒”。
5. 所有动作回写 Profile、CRM 和行为日志，形成下一轮推荐的上下文。

## 设计原则

- 个性化的核心是记忆，不是布局。
- 入口页的第一目标是减少判断成本，不是展示产品能力。
- 聊天适合作为输入层和解释层，完整结果应落到报告、表格、CRM 或任务页。
- 自动化默认停在人类审批门前，尤其是外部触达、扣费、状态变更等写操作。
- 可配置工作流应从高质量模板开始，避免让普通用户面对空白流程图。

## 验证清单

- 新用户 10 分钟内能生成第一版 Profile，并立刻影响推荐结果。
- 老用户再次登录时，首页能回答“今天最该做哪 3 件事”。
- 同一个搜索需求，在不同 Profile 下会产生不同筛选、排序或排除结果。
- 推荐、背调、触达、跟进至少有一条端到端链路能自动串起。
- 用户完成或驳回任务后，系统会把原因写回 Profile/CRM，而不是只更新 UI 状态。
