# Pattern: Freeze phase-scoped evidence catalogs

## 一句话结论

大型遗留系统的证据图谱不能只依赖全局“名称相同即同一对象”；每个分析阶段应冻结自己的路径快照、记录目录和输出白名单，再由父阶段通过哈希引用子阶段，防止同名窗体、DFM 或数据库对象被错误合并。

## 问题背景

遗留代码中常见复制窗体、不同目录下的同名单元、历史版本残留以及跨模块复用表。若稳定 ID 只由短名称生成，两个语义不同的对象可能得到同一身份；后生成的记录会覆盖前者，或在跨阶段汇总时制造并不存在的关系。

## 实现模式

1. 在阶段开始时冻结精确输入范围：相对路径、文件哈希、所属模块和选择理由。
2. 记录身份至少包含证据类型、阶段/模块限定和规范化相对路径；短名称只作为展示字段。
3. 每个子阶段发布固定文件白名单与独立 `summary.json`，摘要包含所有输入、输出和子摘要 SHA-256。
4. 父阶段只消费已提交的子阶段输出，不重新打开原始源码或替子阶段改写事实。
5. 加载时拒绝缺失记录、重复限定身份、未知输出文件、哈希漂移及一个引用解析到多条记录。
6. 同名但证据冲突的对象分别保留；通过显式 relation/decision 连接，不能静默合并。
7. 生成器在临时目录完成全套校验后原子替换，并用不同哈希随机种子证明顺序确定。

## 为什么父阶段只引用冻结子阶段

- 子阶段的覆盖分母不会在父阶段运行时悄悄变化。
- 纠错必须留下新的提交和摘要哈希，而不是无痕覆盖历史结论。
- 父阶段专注跨模块关系与守恒式，不会再次解释按钮、字段或函数。
- 任一结论都能沿父记录、子记录、相对路径和 SHA-256 回到原证据。

## 常见错误

- 用 `FormName`、`UnitName` 或表名作为全局唯一键。
- 父阶段重新扫描源码并覆盖子阶段记录。
- 只校验记录总数，不校验精确 ID 集合和输出白名单。
- 把未知项从新阶段输出中删除，造成覆盖率看似提高。
- 对同名冲突取“最后写入者”，却不生成冲突诊断。

## 验证清单

- 每个阶段有精确输入快照、输出白名单和摘要哈希。
- 同名不同路径对象拥有不同限定身份。
- 父阶段输入只来自冻结子输出，源码访问测试会失败阻断。
- 缺失、额外、重复、跨阶段串用或哈希变化均能触发阻断诊断。
- 两个 `PYTHONHASHSEED` 下生成文件逐字节一致。

## 证据范围与晋级条件

当前在同一 ERP 的采购、销售、库存成本、应收应付和跨模块父阶段中重复验证。跨项目推广前，应再验证一种非 Delphi 资产体系，确认路径限定、版本分叉和父子摘要协议仍能阻止错误合并。
